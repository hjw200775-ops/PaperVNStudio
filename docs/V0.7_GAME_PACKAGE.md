# V0.7 正式版：独立游戏包（Windows x64）

基线 `6631cd6`（V0.6.2，已人工验收），打包版本 `0.7.1`。把内置示例《晚风经过二楼走廊》第一章节选做成**双击即玩、断网可玩**的 Windows 发布包：应用图标、版本信息、单文件便携版与解压目录版，以及一条可用的代码签名管线。

不在本轮范围：通用「导出 Windows 游戏」按钮、NSIS 安装包（带开始菜单与卸载项）、自动更新、多平台。签名证书需要你自己购买/申请，本轮只留接口不伪造信任。

## V0.7.2 的交互修复对这份产物的影响

`game/` 壳里的页面同样来自 `dist/game-html.js`，播放器 CSS 与导出的 HTML 是同一份。V0.7.2 修掉「台词可选中、立绘可拖出缩略图」后，这份产物**只要重新运行 `npm run game:build` 就会带上修复**，不需要改 `game/main.cjs`。

本仓库 `release/game/` 下的 0.7.0 / 0.7.1 包是历史发行产物，按「保留历史产物」没有重建；它们的行为与发布时一致（仍可选中文字）。

## 二、身份与存档隔离

| 项 | 值 |
| --- | --- |
| appId | `cn.papervnstudio.game.wanfeng-ch01`（编辑器是 `cn.papervnstudio.desktop`） |
| productName / EXE | `晚风经过二楼走廊` / `晚风经过二楼走廊.exe` |
| 用户数据目录 | `%APPDATA%\PaperVNStudio-Game-wanfeng-ch01` |
| 页面来源 | `wanfeng://game/index.html` |
| 存档键 | `paper-game-sample-wanfeng-ch01`（播放器原有规则：`paper-game-<工程 id>`） |

三处存档落在三个互不相交的存储里：

| 位置 | 存储 | 内容 |
| --- | --- | --- |
| 纸间编辑器 | `%APPDATA%\PaperVNStudio\Local Storage`（默认会话） | 编辑器自己的状态；工程本身写用户选的工程目录 |
| 内置示例体验 | `%APPDATA%\PaperVNStudio\Partitions\papervn-sample` | 示例的独立持久分区 |
| 本游戏包 | `%APPDATA%\PaperVNStudio-Game-wanfeng-ch01` | 只有这份游戏的存档与音量偏好 |

**移动不影响读档**：userData 由 `app.setPath('userData', …)` 在启动时固定，跟 EXE 所在路径无关；页面来源固定为 `wanfeng://game`，localStorage 的 origin 也不会随目录变化。解压目录版与单文件便携版共用同一份存档。

## 三、应用图标与版本信息

- 源文件是矢量 `game/icon/icon.svg`（深绿纸面 + 傍晚亮着的二楼窗 + 一页正文），不含文字，小尺寸不会糊成一团。
- `npm run game:icon` 用 Electron 自带的 canvas 逐档重采样出 16/20/24/32/40/48/64/128/256 九档 PNG，再打包成多尺寸 ICO（`game/build-resources/icon.ico`，112.5 KB）。不依赖 ImageMagick，也不联网。
- 构建时把 ICO 交给 electron-builder，EXE 与单文件便携版都会嵌入同一套图标。核对方式是直接读 PE 资源表：两份产物都是 `9 档 · 16x16…256x256@32bpp`，而原版 `electron.exe` 只有 4 档。
- 版本资源由 electron-builder 写入并由实测确认：`FileDescription / ProductName = 晚风经过二楼走廊`、`CompanyName = 黄嘉文`、`FileVersion = 0.7.1`、`ProductVersion = 0.7.1.0`、`LegalCopyright = Copyright © 2026 黄嘉文`、`LegalTrademarks = 晚风经过二楼走廊`。

## 四、代码签名

签名没有证书就签不出「受信任」的包，所以本轮做的是**可用的签名管线 + 如实的状态记录**：

```powershell
# 有 .pfx 时（CI 或本机都行）
$env:CSC_LINK = "D:\certs\wanfeng.pfx"      # 也接受 WIN_CSC_LINK
$env:CSC_KEY_PASSWORD = "******"
npm run game:build
```

- electron-builder 会用它给 `晚风经过二楼走廊.exe`、单文件便携版与内部 elevate.exe 依次签名。
- 构建脚本不再把「签名」写死：它读 PE 证书表（数据目录第 5 项）判断是否真的有 Authenticode 签名，结果写进 manifest 的 `signature.signed` 与 `portable.signature.signed`。
- 当前环境没有证书，manifest 明确记为 `signed: false`，`试玩说明.txt` 里也写明「未附带代码签名证书，Windows 可能提示未知发布者，校验请比对 SHA-256」。
- 自签名证书能签但建立不了公共信任链，除内部测试外没有意义，本轮没有做。

拿到证书（OV/EV 代码签名证书，或 Azure Trusted Signing 账号）后，只需设好上面两个环境变量重跑一次构建，验收脚本会核对签名位与时间戳。

## 六、怎么构建、怎么验收

```bash
npm run game:icon                  # 只在图标改动后需要；产物已入库
npm run game:build                 # ZIP + 单文件便携 EXE + manifest（含各自 SHA-256）
npm run game:build -- --prune      # 先清掉更早的中间产物再构建
npm run game:acceptance            # 解压 ZIP、跑真实 EXE 全流程，并单独验收单文件版
npm run game:acceptance -- --no-editor            # 跳过编辑器 / 内置示例交叉验证
npm run game:acceptance -- --portable=<exe>       # 指定单文件便携版
```

中间产物在 `release/game/build/<时间戳>/`（约 376 MB，都是 gitignore 的构建产物）。构建默认不删旧目录：整目录删除在受限环境里会被安全策略拦下，宁可留垃圾也不绕过；需要回收空间时用 `--prune`（会清 `build/*` 与早期版本的 `out/`、`pkg/`），或在资源管理器里手动删除。

## 八、已知限制

- 未签名：SmartScreen 会提示「未知发布者」，需要真实证书才能消除；本包不伪装已签名。
- 单文件便携版每次启动都要自解压，本机实测约 9.6 s（解压目录版约 1.1 s）；杀毒软件对自解压包更敏感。
- 强制结束进程（任务管理器结束任务 / `taskkill /F`）可能丢最后一次保存：localStorage 由 Chromium 异步落盘，正常关窗会 `flushStorageData()` 后才退出。
- 存档仍是播放器原有的单槽设计；没有自动更新（包内不含网络能力）。
