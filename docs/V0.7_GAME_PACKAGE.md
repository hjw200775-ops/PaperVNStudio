# V0.7 第一阶段：独立游戏包（Windows x64 便携版）

基线 `6631cd6`（V0.6.2，已人工验收），版本 `0.7.0`。本轮把内置示例《晚风经过二楼走廊》第一章节选做成**双击即玩、断网可玩**的 Windows 便携包，并把构建与验收脚本固化下来。

不在本轮范围：通用「导出 Windows 游戏」按钮、安装包（NSIS）、单文件 EXE、代码签名、图标、多平台。播放器壳验证通过后再接通用导出。

## 一、构建路径

```
dist/samples/wanfeng-ch01/           内置只读示例（45 节点 / 8 图 / 0 音频）
        │  project-store.diskToRuntime（与编辑器同一条读取路径）
        ▼
dist/game-html.js → dist/export.js  唯一的「工程 → 自包含 HTML」入口
        │  内联 player.js、core.js、effects.js 与全部 data: 图片
        ▼
content/index.html（18.5 MB，零外部请求）
        │  放进独立播放器壳 game/
        ▼
electron-builder --win --x64 --dir  →  win-unpacked/
        │  Electron 45.3.2 取自本机 node_modules/electron/dist，全程不下载
        ▼
scripts/zip-writer.cjs  →  「解压目录 + EXE + 运行资源」ZIP
```

素材没有重新导入、没有重新编码，也没有新增任何图片或音频：标题图仍是 `asset_title_home_corridor`（家中二楼走廊），正文首句仍是早餐场景，`road_17` 的人物特写（scale → 120%）与背景虚化（blur → 8）沿用已确认设置，台词一字未改。

## 二、身份与存档隔离

| 项 | 值 |
| --- | --- |
| appId | `cn.papervnstudio.game.wanfeng-ch01`（编辑器是 `cn.papervnstudio.desktop`） |
| productName / EXE | `晚风经过二楼走廊` / `晚风经过二楼走廊.exe` |
| 用户数据目录 | `%APPDATA%\PaperVNStudio-Game-wanfeng-ch01` |
| 页面来源 | `wanfeng://game/index.html` |
| 存档键 | `paper-game-sample-wanfeng-ch01`（播放器原有规则：`paper-game-<工程 id>`） |

三处存档落在三个互不相交的存储里：

| 位置 | 存储 | 内容 |
| --- | --- | --- |
| 纸间编辑器 | `%APPDATA%\PaperVNStudio\Local Storage`（默认会话） | 编辑器自己的状态；工程本身写用户选的工程目录 |
| 内置示例体验 | `%APPDATA%\PaperVNStudio\Partitions\papervn-sample` | 示例的独立持久分区 |
| 本游戏包 | `%APPDATA%\PaperVNStudio-Game-wanfeng-ch01` | 只有这份游戏的存档与音量偏好 |

**移动解压目录不影响读档**：userData 由 `app.setPath('userData', …)` 在启动时固定，跟 EXE 所在路径无关；页面来源固定为 `wanfeng://game`，所以 localStorage 的 origin 也不会随目录变化。

## 三、播放器壳的安全边界

`game/main.cjs` 只有约 180 行，没有 preload、没有 IPC、没有编辑器入口：

- `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`、`nodeIntegrationInWorker: false`、`webSecurity: true`；不给 `preload`，渲染进程拿不到任何桥。
- `wanfeng://` 协议白名单只服务 `content/index.html`，其余路径 404；不读包外文件、不接受参数与目录穿越。
- CSP：`default-src 'none'`，只放开内联脚本/样式与 `data:` 图片音频，`connect-src 'none'`；`script-src` 的 `'unsafe-inline'` 是「单文件零请求」的实现代价，页面来源固定，不存在外部页面注入面。
- 所有 `http(s)/ws(s)/ftp` 请求在 `webRequest.onBeforeRequest` 直接取消；权限申请一律拒绝；`will-navigate`、`window.open`、`webview` 全部拒绝。
- 单实例锁：重复双击只把已有窗口提到前面，避免两个进程写同一份存档。
- `before-quit` 时 `session.flushStorageData()`，避免「保存后立刻关窗」把存档留在内存里。
- 正式包 `devTools: false`；验收脚本用 `PAPER_GAME_DEVTOOLS=1` 打开远程调试，沙箱与隔离配置两种情况下完全相同（实测不开该变量也能连上，所以本次验收没有用它）。

## 五、怎么构建、怎么验收

```bash
npm run game:build                 # 生成 release/game/<…>-独立试玩包.zip + manifest.json
npm run game:build -- --prune      # 先清掉更早的中间产物再构建
npm run game:acceptance            # 解压 ZIP，驱动真实 EXE 跑完整验收
npm run game:acceptance -- --zip=<zip> --no-editor   # 指定包 / 跳过编辑器交叉验证
```

中间产物在 `release/game/build/<时间戳>/`（约 376 MB，都是 gitignore 的构建产物）。构建默认不删旧目录：整目录删除在受限环境里会被安全策略拦下，宁可留垃圾也不绕过。

## 六、本机实测结果

验收对象是**解压后的 ZIP**，不是源码启动。解压路径带中文与空格：`%TEMP%\晚风 试玩 验收\<时间戳>\`。

| 检查 | 结果 |
| --- | --- |
| 解压后双击 EXE，窗口直接是标题页 | 通过（启动约 1.2 s） |
| 标题文字与家中二楼走廊背景 | 通过（背景是内嵌 `data:image/png`，无缺失提示） |
| 断网（页面内 `fetch` 外网） | 通过（被拦截，包内无远程引用） |
| 从头玩到 `demo_end` | 通过（45 句逐句比对正文与说话人，全部图片加载成功） |
| 正文背景 / 两名角色表情 | 通过（开场「自然/平静」，`road_17` 轻恼，`road_18` 轻恼/微笑） |
| `road_17` 演出 | 通过（人物特写 120%，背景虚化按 1280 画布换算 6.88 px） |
| 保存 → 关窗口退出进程 → 重开继续 | 通过（回到第 25 句「林澈！」） |
| 移动整个解压目录后再读档 | 通过（改名并搬到另一个含中文空格的目录，仍回同一句） |
| 游戏存档与编辑器 / 内置示例互不影响 | 通过（游戏键只在游戏 userData；编辑器默认存储无此键；示例另写一份存档后游戏仍回原句） |
| ZIP 清单 | 通过（79 条目 / 77 文件；无编辑器入口、工程文件、本机路径；中文名为 UTF-8） |

**未验证**：第二台未安装纸间与开发环境的 Windows 电脑断网启动。本机只有一台，按实际记录，不标通过。

## 七、已知限制

- 强制结束进程（任务管理器结束任务 / `taskkill /F`）可能丢最后一次保存：localStorage 由 Chromium 异步落盘，正常关窗会 `flushStorageData()` 后才退出。这是 Electron 的常见行为，写在这里而不是藏起来。
- 首版没有应用图标（用 Electron 默认图标）、没有代码签名，SmartScreen 可能给出「未知发布者」提示。
- 存档仍是播放器原有的单槽设计；音量偏好与存档同目录，但键不同。
- 没有自动更新；包内不含任何网络能力，所以也不可能有更新检查。
