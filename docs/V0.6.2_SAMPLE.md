## 二、原作示例工程

来源为用户本机既有 45 节点原作工程。核验依据是内容而不是目录名：

- 45 个节点，首节点 `home_01`，结尾 `demo_end`（`type: 'end'`）。
- 林悠、林澈两个角色，各 2 个表情；台词绑定与同场表情都在。
- 7 张原作素材（3 张正文背景 + 4 张人物）引用有效。
- `road_17` 保留人物特写（`scale → 120`）与背景虚化（`blur → 8`）。
- 1 个章节、3 个段落（早餐 / 上学路 / 学校走廊）。
- 无 `audioAssets`：没有混入英文占位语音或测试音效。

生成脚本 `scripts/build-sample.cjs`（`npm run sample:build`）从**主工程文件**（不是 autosave）读取，先记录源目录全部文件的哈希，生成后再比对，源工程零改动。输出只包含 `project.paper.json`、`assets/images/` 与 `NOTICE.json`；首次保存会产生的 `backups/latest` 在生成后删除。

内置模板位于 `dist/samples/wanfeng-ch01/`，随 `dist/**` 一起进安装包，运行时用相对路径定位（`path.join(__dirname, '..', 'dist', 'samples', …)`），不硬编码任何开发机路径。

## 三、标题背景的数据设计

- 字段：`p.titleBackground`，字符串，值是 `p.assets[].id`；空串表示默认标题页样式。不保存本机路径、不复制图片、不新增素材类型。
- 校验：`C.validate` 只检查「是字符串且长度合理」。素材是否存在由 `C.analyze` 报告，因为缺图应当回退默认样式，而不是让整个工程打不开。桌面存储层的 `validateDisk` 同样只校验类型。
- 迁移：`C.migrate` 给缺字段的工程补空串（含 schema 1–4 的升级路径）。**没有升 schema 版本号**：这是可选的增量字段，正文、分支、存档都不受影响。
- 为什么不算「向后兼容」：新版能读旧工程；但旧版本（V0.6.1 及更早）保存含标题背景的工程时会**静默丢弃** `titleBackground`，标题图丢失、工程仍可打开。这一点与 V0.5 的音频字段一致，已在 README 与已知限制里写明，不当成兼容承诺。
- 存读：`toDisk` / `validateDisk` / `diskToRuntime` / `inspectReferences` 都带上该字段，保存、另存为、备份恢复、撤销重做（`snapshot()` 展开整个工程）都保留。

## 四、播放器行为

- 标题页结构：`#titleScreen > #titleBg > img` + `.title-card`。有背景时 `#titleScreen` 变成固定铺满视口、内容居中的容器，图片 `object-fit: cover`，左侧叠一层渐变保障标题和按钮对比度；小窗口可滚动，标题与三个按钮不会被裁掉。
- 缺素材：容器整体隐藏，卡片下方显示「标题页背景素材缺失，已使用默认标题页样式。」，「开始游戏」仍可用；`window.paperGameState().titleBg` 供自动化断言。
- 标题页依旧不创建播放层、不自动播放 BGM；本版没有标题音乐。
- 编辑器导出的 HTML、编辑器的「完整预览」、内置示例体验共用 `dist/game-html.js` 的 `buildPlayerHTML()`，不存第二套拼装逻辑。

## 五、内置示例的产品行为

- 位置：编辑器左栏「标题页」标签顶部卡片，显示《晚风经过二楼走廊》「第一章原作节选 · 45 个节点」、作者与素材说明。
- **体验示例**（桌面）：主进程读取模板 → `buildPlayerHTML` → 写到 `userData/sample/game-sample.html` → 独立窗口加载。
  - 窗口使用 `partition: 'persist:papervn-sample'`，存档落在 `userData/Partitions/papervn-sample`，不写安装目录。
  - 模板工程 ID 固定为 `sample-wanfeng-ch01`，所以两次体验读到同一份存档。
  - 不设置 `currentDir`、不写草稿、不动最近工程；模板文件只读。
- **复制示例开始创作**（桌面）：先走已有的未保存修改保护，再选目录；只有**空目录**才会复制，复制后把工程 ID 换成新的随机 ID，按普通工程打开并加入最近工程。取消不生成任何文件；目录非空直接拒绝；写入失败只清理本次创建的文件（`project.paper.json` / `assets` / `backups` / 残留 `.tmp-*`），目录本身保留。
- **网页版**：不能选目录，只显示「下载示例工程」——把模板与素材组装成单文件 `.paper.json` 下载，再用「打开工程」导入。没有假装完成桌面式复制，也没有第二套文件系统。
- 模板与副本、作者原工程的存档键分别是 `paper-game-sample-wanfeng-ch01`、`paper-game-<新 UUID>`、`paper-game-wanfeng-ch01-canon-v1`，互不串用。

## 六、安全边界与打包

- 新增 IPC 三个固定通道：`sample:info` / `sample:experience` / `sample:copy`。渲染进程不传路径、不传内容，只发空参数；源目录由主进程自己决定，沿用现有的发送方与 `paper://app/` 来源校验。
- 示例窗口没有 preload、`sandbox`、`contextIsolation`、`nodeIntegration: false`，与「完整预览」同级别。
- 打包：`build.files` 已包含 `dist/**`，示例随之分发；只捆绑必要文件（无 backups、测试报告、截图、原稿参考包、API Key）。安装资源目录保持只读——所有写操作都在 `userData` 或用户选择的目录。

## 九、已知边界

- 标题背景只有一个图和一个默认样式，没有主题编辑器、标题音乐、标题动画或多套版式。
- 示例模板是完整副本，副本体积与原作相同；升级不会覆盖用户副本，但也不会自动同步模板更新。
- 旧版本保存会丢弃标题背景字段（标题图丢失），只能靠「不用旧版保存 + 保留备份」防护。
- 网页版没有体验与复制，只有下载。
