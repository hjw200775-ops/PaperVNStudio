| 项目 | 实测 |
|---|---|
| 首次播放（真实 OGG 解码到可播） | 100–246 ms（两次运行） |
| 线性淡入 1.6 s | 15 个采样点 0 → 0.80，单调上升 |
| 等功率交叉淡化 1.5 s | 中途采样 0 / 0.10 / 0.29 / 0.39 / 0.49 / 0.57 / 0.63 / 0.69 / 0.74 / 0.78 / 0.79；峰值 0.80；终值 0.80 |

## 4. 《晚风》音频演出样板（M7）

`node scripts/build-wanfeng-audio.cjs` → `release/wanfeng-v081-audio.json`

- **隔离副本**：在 V0.8.0 演出工程的磁盘副本上叠加音频动作，原工程与原始素材未改动；
  新工程 `release/wanfeng-v081/audio/`。
- **BGM 来自仓库自带 OST**（`dist/samples/wanfeng-ch01`）：九月的早晨 / 桂花香的小路 / 灯还亮着，
  外加标题曲「晚风经过二楼走廊」。**没有修改任何原始音频文件。**
- **音效与「配音」是脚本合成的 WAV**，文件名写明「合成占位」：风铃（1.2 s）与
  五音节包络的独白占位（3.2 s）。它们只用于验证 Ducking 与语音互斥，**不代表真实配音**。
- 三段的音频编排：

| 片段 | 音频动作 |
|---|---|
| 清晨的相遇 | `audio.bgm.play`（70%，淡入 2.6 s，整曲循环）+ `audio.ducking` 参数配置 |
| 放学后的走廊 | `audio.bgm.crossfade`（等功率 2.5 s，与画面交叉淡化同一时刻）+ 闪白时 `audio.sfx.play`（风铃，key=chime） |
| 夜晚的房间 | `audio.bgm.crossfade`（线性 3 s，区间循环 4–34 s）+ `audio.voice.play`（触发 Ducking）+ `audio.voice.stop` + 收尾 `audio.bgm.stop`（淡出 4 s） |

- **标题音乐循环演示**：`titleMusic` 带区间 6–14 s，播放器按区间回跳（见第 3 节实测 3 个循环）。
- **可试听产物**：`release/wanfeng-v081/晚风经过二楼走廊·音频演出版.html`（36.2 MB，单 `<script>`，素材全内嵌），
  双击即听，断网可用。

> 原始版本对照：`release/wanfeng-v080/晚风经过二楼走廊·演出优化版.html`（29.6 MB，只有画面演出、无音频动作）。
> 两者同一份台词与画面，差异只在音频动作，可直接对听。

## 5. 未完成项与验证边界（如实说明）

1. **没有人工试听**。全部结论来自增益曲线、实例数量与播放位置。按任务书要求，本轮标记为
   **「技术验收通过，听感待确认」**，不宣布音质或主观听感合格。
2. **载体只跑了单文件 HTML**。目录版游戏与 Windows 免安装版本轮没有跑音频实机（V0.8.0-RC 已验证
   同一播放器的画面演出）；编辑器「完整预览」窗口也没有单独跑音频，只验证了面板渲染与降级路径。
   三者共用同一个 `paper.js` 播放器与同一个音频工厂，但没有实测证据就不算通过。
3. **1 GiB 大型工程音频回归未做**。本轮只测了引擎实例稳定性（100 次切换）与渲染堆，没有在 1.5 GB
   工程上跑「打开 → 切曲 → 演出 → 存档 → 导出」。这一项是本轮最明显的缺口。
4. **循环接缝不是采样级**。本机验收窗口无前台合成器（rAF 不触发、定时器被节流到 ~1 s），
   实测接缝 平均 330 ms / 最大 984 ms；代码在可见窗口下按帧检查，但本机没有取得前台样本。
5. **音频素材本身的制作问题不由播放器掩盖**。样板里的三首 OST 直接使用原文件，没有做淡入淡出裁切或
   重新编码；若原曲在接缝处本身有配器突变，报告中如实保留，不做修补。
6. **面板只做了功能接线与静态验证**：7 个音频预设、参数控件、试听按钮都已接上，
   但没有人手在编辑器里逐项试听确认手感。
