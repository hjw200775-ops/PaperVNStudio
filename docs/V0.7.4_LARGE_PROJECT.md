# V0.7.4 大型工程预览与资源加载优化

基线 `09f737d`（V0.7.3）。本版解决一个具体的天花板：**完整预览把整份自包含 HTML 经 IPC 传给主进程，素材越多 HTML 越大，91.8 MB 的工程直接撞上 64 MB 限制。**

## 一、问题与根因

旧链路：编辑器 `exportHTML()` 生成单文件 HTML（素材全部 base64 内嵌）→ `ipcRenderer.invoke('player:preview', html)` → 主进程写 `userData/preview/game-preview.html` → `loadFile`。

三处被同一个数字卡住：HTML 体积、IPC 传输量、Chromium 解析的文档大小。31 张立绘 + 19 张背景 + 6 首 BGM 就已经 91.8 MB，后续还有事件 CG、动态立绘、15 首 BGM，提高上限只是把墙往后挪。

## 二、新架构

```
编辑器（渲染进程）
   │  只传工程数据（不传 HTML）
   ▼
主进程
   ├─ 会话目录 userData/preview-sessions/s-<id>/
   │    ├─ index.html      轻量播放器（只有 CSS/JS/剧情数据）
   │    └─ assets/<sha256>.<ext>   图片与音频，内容寻址去重
   ├─ 注册 pvres:// 协议（只认活跃会话、路径必须落在该会话目录内）
   └─ loadURL('pvres://<id>/index.html')
```

- 播放器代码、音频层、演出逻辑一行没改：`assets[].data` 从 data URI 换成 `pvres://` 地址，`<img>.src` 与 `<audio>.src` 本来就能接受任何 URL。
- 剧情数据仍内联在 HTML 里（几百 KB），资源按需读取；`#layers` 的图片在进入对应句子时才发请求。
- 安全边界不变：`sandbox` + `contextIsolation` + 无 preload/Node，HTML 走自定义协议并带 CSP（`img-src 'self' data:`、`media-src 'self' data:`、`connect-src 'none'`），协议 handler 校验会话与路径，预览窗口拿不到任意文件。
- 未保存的编辑结果照样进预览：传的是当前内存工程，不是磁盘上的旧文件。

## 三、资源引用分析（M1）

`core.referencedImageIds()` 与已有的 `referencedAudioIds()` 同口径：

| 类型 | 收集范围 |
| --- | --- |
| 图片 | 标题背景、**所有节点**的图层（含未走到的分支）、角色表情表里的 `assetId` |
| 音频 | 所有节点 `bgm/sfx/voice`、标题音乐 |

按「全部节点」而不是当前试玩路线收集，所以分支素材不会漏；没被任何图层或表情引用的备用立绘会被判为未引用，**只从播放产物里排除，不动工程目录**。

`scripts/resource-report.cjs` 可以对任意工程目录直接出清单（不加载 data URI）：

| 工程 | 素材库 | 实际引用 | 排除 | 引用占比 |
| --- | --- | --- | --- | --- |
| 大型合成工程（60 图 / 6 曲 / 48 节点） | 228.5 MB | 174.6 MB | 53.9 MB（13 图 + 5 曲） | 76.4 % |
| 《晚风》示例（8 图 / 6 曲 / 45 节点） | 21.8 MB | 18.4 MB | 3.3 MB（3 曲） | 84.7 % |

## 四、导出（M3）

`buildGameHTML` 现在同时按引用收图片与音频，并在 `manifest.resources` 里记录：

```json
"resources": {
  "mode": "inline",
  "images": { "library": 60, "included": 47, "excluded": 13, "bytes": { "library": 221298780, "included": 173350711 } },
  "audio":  { "library": 6,  "included": 1,  "excluded": 5,  "bytes": { "library": 7327121, "included": 1269067 } },
  "dataBytes": 12345678, "htmlBytes": 23456789
}
```

单文件 HTML 的断网能力不变（素材仍是 data URI）。**没有**降画质、重压缩音乐或删原素材。

> 独立 Windows 游戏包本轮只做兼容性检查：导出仍走单文件内嵌，`MAX_CONTENT_BYTES` 保持 64 MB。把大型资源分离打包（包内目录 + 运行时读取）是下一阶段的任务，本轮不扩大范围。

## 五、生命周期与提示（M4 / M5）

- 关闭预览窗口 → 该会话目录异步删除；主进程启动时再清一次 `preview-sessions/`，异常退出也不会堆积。
- 重复打开：先关旧窗口（触发旧会话清理），再建新会话；两次会话的 `id` 不同，互不干扰。
- 预览窗口的音乐在 `pagehide` 释放（V0.7.3 已有），关窗不会留声。
- 预览失败只影响状态提示与 toast，不碰工程与草稿；`player:preview` 出错时会话目录当场删掉。
- 编辑器「舞台预览」标题旁有一行小字：正在准备预览 / 正在生成播放器 / 正在加载游戏 / 预览失败（红字给原因）。完成后 1.5 s 自动消失。
