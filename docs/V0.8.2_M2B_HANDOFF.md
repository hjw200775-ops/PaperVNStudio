## 2. M2B 六项核心问题的落地方案

### 2.1 音频事件如何依据时间轴执行

- 预览控制器每帧 `onTick(t)` 给出**当前绝对时间**（单调时钟，M2A 已实现）。
- 用 `PF.schedule(actions)` 得到全部动作的绝对 `start`；按类型分两类：
  - **状态音频**（`audio.bgm.* / audio.bus.volume / audio.ducking`）：由
    `PF.stateAt(before, actions, t, ctx).audio` 求目标状态，用 `runtime().applyAudioState(st.audio)`
    落地（同一首不重启）。这是 V0.8.1 跳过/读档路径的既有语义，**不要从头重放历史动作**。
  - **一次性音频**（`audio.sfx.* / audio.voice.*`）：只在上一次时间 `lastT` 与当前 `t` 构成的
    区间 `(lastT, t]` 内、且 `start` 落入该区间的事件才触发。
- `TL.audioSideEffectsAt(actions, t)` 目前只按「精确等于 t」过滤，**不满足区间跨越语义**；
  M2B 需在 `timeline.js` 增加 `audioSideEffectsBetween(actions, from, to)`（半开区间、去重、按 start 排序）。
- 触发执行复用 `app.js` 的 `perfAudioAction(a)`（`A.pure.audioActionSpec` → runtime 调用），
  不要另建一套音频调用。

### 2.2 从任意时间开始播放时如何恢复持久 BGM 状态

- `previewStart(from)` / `previewSeek(t)` 时：
  1. `before` 取「进入本句前状态」（M1A/M2A 用 `PF.emptyState()`；若要与游戏完全一致，
     参考 `perfReplayState()` 沿路径重放，属跨模块状态恢复，见第 6 节）。
  2. `st = TL.scrubState(before, actions, t, ctx)` → 取 `st.audio`（含 `bgm.audioId/volume/loop`、
     `buses`、`ducking`）。
  3. `runtime().applyAudioState(st.audio)` 一次性落地，不播放 `[0, t)` 的历史切换过程。
- 参考 V0.8.1 的 `enterAudioInto(id, 'rebuild')`：读档/定点试玩按目标句状态从曲首重建 BGM。
- 明确区分 **A 时间轴演出循环预览**（M2A 视觉）与 **B BGM 素材精确音乐循环**（V0.8.1 既有），
  `st.audio.bgm.loop` 属于 B，不应被预览区间覆盖。

### 2.3 如何避免重放历史 SFX 和 Voice

- 维护播放会话内的 `lastT` 与 `generation`；只在**正常向前推进**时扫描 `(lastT, t]`。
- `previewSeek` / `previewStop` / `previewPause` / `previewLoop` 一律重置 `lastT` 并清空待触发队列：
  - 循环从 `b` 回到 `a` 时 `lastT = a`，只触发 `[a, t]`，**绝不重放 `[0, a)` 的历史一次性音频**。
  - 向后定位（seek 到更小 t）不补播已经过去的音效。
- `stateAt()` 本身是纯函数、不含一次性音频对象（M1A/M2A 测试已断言 `'sfx' in st === false`），
  这条不变式必须保持。

### 2.4 暂停及定位如何取消旧音频任务

- `previewPause / previewStop / previewSeek` 事件到达时：
  - 清空所有挂起的 `setTimeout` 调度（参考 `app.js` 的 `clearPerfAudioTimers()`）。
  - 递增 `generation`；所有异步结果返回前校验 token，过期即丢弃（参考 `audio.js` 的
    `loadSeq` 与 `start(ch, myGen)` 的代际保护）。
  - 收尾当前一次性播放：`runtime().sfxStop(key)` / `voiceStop()`；BGM 按目标状态淡出或保持，
    由 `applyAudioState` 决定，不要并行创建新的 gain 节点。
- 暂停时视觉状态停在 `curT`（M2A 已实现），音频任务必须同步停，避免"画面停了声音还在"。

### 2.5 如何与现有 Audio Engine 和 AudioParam 调度协作

- `audio.js` 的 `bgmVolume / setBusVolume / setDucking / bgmCrossfade` 内部已用
  **AudioParam ramp** 做渐变；M2B 只在「目标状态变化」时调用，**不要每帧重设参数**（会与 ramp 打架）。
- 淡入淡出使用 `bgmCrossfade({duration, curve})` 的既有参数；`audio.bgm.play` 的 `fadeIn`、
  `audio.bgm.crossfade` 的 `duration/curve` 已在 `perfAudioAction` 里映射好。
- 精确循环与 64 MiB 解码缓存、流式回退、`playbackStats()` 全部沿用，不重写。
- 需要"试听接缝/循环点"时用 `runtime().loopPreview()`（M3 既有），但它与主 BGM 槽分离，
  M2B 不能把它当正式播放通道。

### 2.6 如何避免双 BGM 和异步竞态

- 统一通过 `applyAudioState` 落地状态音频；用 `runtime().snapshot().dualBgm` 作为回归断言
  （V0.8.1-RC3.1 已修复 `enter(rebuild)` 双 BGM 缺陷，经验必须保留）。
- 所有 `bgmCrossfade` / `loadBuffer` 异步结果带 generation token；`previewStop/Resume/Seek`
  递增代际，旧结果不得覆盖新状态（参考 M2A 波形层的 `scope/epoch` 与串行请求）。
- 同一素材的 `decodeWaveform` 并发会互相判 `stale`（因为共用 `loadSeq`）；
  M2A 已用串行队列规避，M2B 若并发解码必须沿用该约束。
- 回归必须包含：快速切换、暂停继续、任意起点、循环 10 次以上、100 次启停，
  并断言 `instances.bgm <= 1`、`playbackStats().failed === 0`、无错误横幅。

## 4. 明确交给 DeepSeek-V4-Pro 的复杂问题（证据）

1. **音频时钟与视觉单调时钟对齐**：M2A 视觉用 `performance.now()`，音频用 `AudioContext.currentTime`；
   两者漂移与延迟补偿需要专项设计（`audio.js` 的 `baseLatency`、`startAt` 已存在但未在时间轴预览里使用）。
2. **跨模块异步状态恢复**：`before` 状态目前用 `PF.emptyState()`；若要与发布游戏完全一致，
   需把 `perfReplayState()` 沿路径重放、`enterAudioInto` 的读档语义与预览 seek 对齐，涉及
   `app.js` / `player.js` / `audio.js` 三方，属跨模块改造。
3. **暂停时的 AudioParam 取消语义**：`stopAll()` 会清所有通道，但预览暂停希望"保留 BGM 位置、
   只停一次性音频"，现有 `audio.js` 没有细粒度 pause 接口；这是引擎级缺口，**记录但不擅自改冻结模块**。

> 再交由专项处理，不要以"兼容性"为由关闭 sandbox/webSecurity 或放宽安全机制。
