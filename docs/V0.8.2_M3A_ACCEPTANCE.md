## 1. M3A-0 架构审查结论

三套运行环境（编辑器时间轴预览 / 编辑器普通试玩 / 正式游戏播放器）**共享同一份演出计划**与**同一套纯函数求值**：

| 共享层 | 模块 | 三环境是否共用 |
|---|---|---|
| 排程（相对/绝对混排、并行、零时长、同刻多事件） | `PF.schedule` | ✅ 共用 |
| 状态求值（终态 + 任意时刻 t） | `PF.stateAt` / `PF.commit` / `PF.replay` | ✅ 共用 |
| 阻塞推进等待点 | `PF.blockUntil` | ✅ 共用 |
| 音频动作归一化 | `A.pure.audioActionSpec` | ✅ 共用 |

「仅需语义一致、不必强行统一」的执行器有三份：`player.js:157 perfAudioAction`（正式播放器，setTimeout 挂动作）、
`app.js:2171 perfAudioAction`（编辑器试玩，setTimeout 挂动作）、`timeline-preview-audio.js` 驱动（onTick 扫描区间，
注入 app.js 的 perfAudioAction）。三者逐字节等价地调用同一批音频引擎 API（bgmCrossfade/bgmStop/sfxPlay/voicePlay/…）。

**审查发现的边界差异（已修复或文档化）**：
1. `stateAt` 是「`t <= start` 跳过」的半开语义，音频副作用在「`t >= start`」触发，二者在 `t == start` 边界互补——
   已在 `tests/runtime-consistency.test.cjs` 固化，不把真实播放塞进 `stateAt`。
2. 三份 `perfAudioAction` 存在漂移风险 → 用一致性契约测试（audioActionSpec 归一化 + 调度序列）固化，不强行合并。

## 2. M3A-1 音画同步精度实测（av-sync-benchmark.json）

真实 Electron 窗口（源码 electron），同步测试节点 12 组「视觉标志（camera.zoom）+ 短促 PCM 音效（sfx_chime）」同刻触发，
分层采集计划时间 / JS 派发时间 / AudioContext 排程 / 在线音频图 RMS。

| 场景 | 样本数 | P50 | P95 | max | 结论 |
|---|---|---|---|---|---|
| **前台热态正常（主指标）** | 34 | 0.8ms | **10.6ms** | 10.6ms | ✅ P95 ≤ 50ms |
| 冷缓存首次播放 | 12 | 8.8ms | 9.4ms | 9.4ms | 单独统计，不混入热态 |
| 短时掉帧（忙循环 ~350ms） | 6 | 2.0ms | 55.2ms | 55.2ms | 单独统计（掉帧尖峰，不用于热态达标判定） |
| 受限环境（CPU throttling ×4） | 13 | 2.4ms | 3.9ms | 3.9ms | 单独统计 |

- 多次实测热态 P95 稳定在 9–11ms 区间（三次运行 9.1 / 9.1 / 10.6ms），均满足 ≤ 50ms。
- 在线音频图 RMS 采样 `[0.007, 0.037, 0.003, 0.063, 0.111, 0.020, 0.051, 0.068]` 持续非零，证明真实发声。
- 测量边界：**仅覆盖「在线音频图 + 渲染层」**，不采集操作系统扬声器/声卡回环输出；AudioContext 排程时间 ≠ 扬声器发声时间。

## 3. M3A-2 音频事件调度稳定性（掉帧处理）

- **持久状态命令**（BGM/总线音量/循环/Ducking）：永远恢复到当前正确状态，从不跳过。
- **一次性音频事件**（SFX/Voice）：短时掉帧（≤ 500ms）按「执行」规则补触发，不无声遗漏；
  严重过期（> 500ms）跳过补发并记录 `skippedStale`，避免渲染恢复后瞬间播放大量历史音效。
- 保留 64 MiB 缓存预算与串行解码，不做无条件预解码；预览会话代际隔离复用既有 `generation`/`loadSeq`。
- 掉帧实测：350ms 忙循环后事件补触发或明确记录跳过，无静默遗漏。

## 4. M3A-3 Voice 暂停与恢复

- `voicePlay(spec.offset)`：从保存位置续播剩余部分（HTMLAudioElement 用 currentTime 恢复，向后兼容）。
- 预览驱动暂停时保存正在播的 Voice 位置与 duck 参数；继续时 `voicePlay({offset})` 续播，不再从头重播。
- 暂停即停止正在播的 Voice；继续续播「已开始未播完」的剩余部分；seek/停止/回绕不重放历史 Voice。

## 5. M3A-4 BGM 状态恢复

- `applyAudioState(state, { offset })`：precise 模式 `AudioBufferSourceNode.start(when, offset)` 原生恢复；
  stream 模式 `currentTime` 恢复；同曲不重启（只调音量/循环）。
- 交叉淡化中途恢复语义：以目标状态瞬时恢复（有损上限，产品语义），不逐样本还原中间增益。
- 合法交叉淡化单 precise 槽不误报双 BGM；`dualBgm` 检测 precise+stream 异常残留。
- 过期异步请求由 `loadSeq` 代际隔离丢弃，不覆盖恢复后的状态（`audio-precise.test.cjs` 既有覆盖）。

## 6. M3A-5 时间轴与正式播放器语义一致性

- `tests/runtime-consistency.test.cjs`：统一演出测试工程（相对/绝对混排、并行、零时长、同刻多音频、阻塞）下，
  调度确定性、stateAt 终态逐字段一致（重复求值 / commit / replay / scrubState 四路等价）、
  边界语义（t=0/start/end/终点/回退）、音频动作序列、blockUntil 全部固化。
- `runtime-consistency.json`：真实窗口里时间轴预览 seek 终态与普通试玩播完终态，
  视觉（镜头/渐暗）与音频（BGM 素材/音量/循环/总线/Ducking）逐字段一致。

## 7. M3A-6 剧情交互与演出调度一致性

- 阻塞演出按既有规则结算（`perfBlocking` → `perfSkip` 到终态，player.js 与 app.js 各自实现但语义相同）。
- 快进/读档用 `PF.commit`/`replay` 重放 trail 求终态，历史 SFX/Voice 不重放（一次性音频不进 stateAt）。
- 分支后旧节点任务由 `generation` 代际取消；BGM 跨节点沿用/重建语义不变（`enter`/`rebuild`）。
- 本轮不开发跨节点时间轴，仅维护单节点时间轴与交互式剧情运行时的一致性。
