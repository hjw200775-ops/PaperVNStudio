# 已知限制与验证边界

## 当前已实现

V0.3 网页基线已保留；本分支另外实现了 Windows 桌面预览版：Electron 独立窗口、受控 `paper://` 资源协议、本地工程目录、内容寻址素材、原子保存与备份、旧工程导入、最近工程与启动恢复，并保持离线 HTML 游戏导出。V0.5 新增基础音频（BGM / 音效 / 台词语音）与统一音频运行层。V0.6.1 为导出作品加入标题页、游戏菜单、设置、单槽继续与返回标题，并提供编辑器「完整预览」。逻辑测试、存储测试、导出测试、安全边界测试、真实 Electron 窗口烟测、音频实机验收与播放器实机验收均已通过。仍未完成人工可见窗口验收、人工听审、另一台电脑验收（见 `docs/ACCEPTANCE.md`）。

## 需要优先处理

1. 网页版仍只在浏览器自动保存一个草稿，切换域名、端口、浏览器或清理站点数据后不会自动迁移；桌面版已改为工程目录 + 自动保存副本 + 备份。网页版迁移仍请下载工程再导入。
2. 运行时模型仍把图片解码为 data URL（内存占用随素材增长）；桌面磁盘格式已改为相对路径 + 内容寻址文件。单图上限 12MiB、工程上限 80MiB 保留。
3. 撤销记录上限 60 步，不跨应用重启；桌面版另有 `backups/` 元数据备份，但不替代版本管理。
4. V0.4.1 已加入角色实体与表情库（每个角色可有多个整图表情变体）；V0.4.2 已加入章节/段落分组与导入预览；V0.5 已加入基础音频，但仍无变量与条件结局系统。表情切换是「整张立绘换图」，不是 Live2D 或分层 PSD 局部换脸。角色与表情已有批量编辑（V0.4.3：勾选多句批量修改说话角色、本句表情与在场角色表情）；音频目前只支持逐句绑定，没有批量音频绑定。
5. 每个节点每个图层每种效果只支持一条起止曲线；不是完整 AE 多关键帧时间轴。持续效果遇到独立场景会重置。
6. 编辑预览按脚本顺序继承，试玩按实际路径；复杂分支的静态预览可能不同，需试玩验证。
7. 读档与后退恢复本句效果终态，不恢复动画中途时间。提前推进时，持续效果按目标值结算。
8. 合成 PNG 只导出原始布局，不包含逐句滤镜和动画。效果随 HTML 游戏导出。
9. 导出播放器包含当前工厂函数，未来模块拆分时要特别验证 HTML 是否仍可独立工作。
10. 当前导出游戏存档键依据工程 ID，重复导出同一工程可共享已有进度；节点被删除后旧存档可能失效。正式版应增加存档版本与迁移策略。
11. 源码较紧凑，可读性有改善空间；不建议同时做大规模整理和文件系统重构。
12. 缺少大规模素材/长篇压力测试、完整跨浏览器矩阵、桌面安全测试、异常断电恢复和 Windows 实机兼容测试。

## V0.5 基础音频的边界

1. 首版切换音乐采用「旧曲淡出 → 新曲淡入」，不做复杂叠轨、交叉淡变或逐轨混音；同一时刻只有一条 BGM 通道。
2. 定点试玩、返回、读档、重开都按目标句状态**从曲首**重建音乐，不追算此前耗时，也不承诺跨会话恢复到音乐的精确秒数。
3. 台词语音每句最多一条、手动导入，不按说话角色自动选音色，不自动等待语音结束推进，不接 TTS / 音色克隆 / 口型同步。语音不阻止玩家继续。
4. 音效每句最多 16 条、同时最多 8 个通道；选项按钮没有专用音频机制（音效绑在选项之后的节点上）。切句会停止上一句未结束的音效并取消延迟任务。
5. 本版可靠支持 16-bit PCM WAV；其他格式只有当前运行环境 `canPlayType` 能接受时才允许导入，不承诺所有浏览器/系统解码相同编码。单文件上限 16 MiB、音频总量上限 96 MiB；时长元数据异步读取，浏览器不给元数据时用 WAV 文件头兜底并明确提示。
6. 分类音量与静音是本机播放偏好（`localStorage`），不随工程走；节点音量属于工程内容。导出的 HTML 带默认偏好，玩家在自己的浏览器里另存一份。
7. 导出 HTML 内嵌全部音频（含当前未被引用的素材），体积随素材增长；导出前会提示增加的体积，超大工程生成可能较慢。
8. 音频素材按内容哈希保存且从不删除；磁盘 `assets/audio/` 会随工程历史增长，首版没有受控回收。
9. 音频路径推导沿用 `entryPlan` 的循环检测与枚举预算。路线太多或存在循环时会停止枚举并提示从更早入口试玩，不会假装路径唯一；同一画面入口前的不同 BGM 不会被 `sceneMode:'own'` 清除。
10. 旧版兼容风险（已在临时副本实测）：V0.4.3 及更早版本能打开含音频工程，但保存时会**静默丢弃 `audioAssets`**，`node.audio` 保留成失效引用（`assets/audio/` 文件仍在磁盘）。请勿用旧版保存含音频工程，并保留备份。后续可考虑 `formatVersion: 2` + `capabilities: ['audio']`，但已发布的旧版不会因为新版加了标识就自动拒绝打开。
11. **未验证项**：人工听审为「待用户试听」（不能声称听感、音色、循环接缝正确）；解锁与音量操作由自动化注入的输入事件完成，不是真人界面操作；第二台电脑与安装包未验证。旧版本已完成的人工/安装包验收未反复重跑。

## V0.6.1 标题页与菜单的边界

1. 单槽手动存档：没有自动存档、多槽、存档命名、跨设备同步；「继续游戏」只认最近一次手动保存。
2. 菜单打开时只暂停剧情输入，不暂停演出与音频；没有独立的暂停/恢复引擎，也没有快进、文本回顾或自动播放。
3. 标题页没有标题音乐、主题编辑或自定义背景；本轮不制作独立游戏 EXE。
4. 继续 / 读档 / 重新开始按目标句状态从曲首重建 BGM，不保存播放秒数。
5. 「完整预览」与导出使用同一份自包含 HTML，但预览是独立 `BrowserWindow`，不是编辑器舞台内嵌；真人操作未单独验收。
6. **未验证项**：真人点击与人工听审（自动化只注入输入事件）；第二台电脑与安装包；较小窗口只做了按钮不裁切检查，未做多分辨率人工验收。

## V0.4.3 批量的边界

1. 批量只作用于对话/旁白节点；选项与结局节点跳过，不参与批量修改。
2. 场景粘贴是整体替换：不合并两套图层，也不搬运源句的演出；有演出引用冲突时该目标不写入。
3. 演出粘贴只支持「同图层 ID」「唯一角色身份」两种自动匹配，其他情况需要逐个处理（本轮不做映射面板）。
4. 批量修改在场的角色表情时，若该句在分支之后画面不唯一，会跳过而不是按某条路线猜。
5. 多选依赖 `nodes` 播放顺序；未分组句子在树里集中显示，但连选仍按数组顺序。

## V0.4.2 章节的边界

1. 章节/段落只是分组：播放顺序仍由 `nodes` 数组决定，章节顺序与数组顺序保持一致，不支持「章节顺序与播放顺序分离」的排法。
2. 从本句/本段试玩按「最后一个独立场景 → 本句」的实际路径还原；多条路线会合并成同一个状态时不再提示，路线不同时必须由作者选择一条，选中的路线只影响这次试玩。
3. 拖动目前用 HTML5 拖放实现，触屏与手柄不支持；键盘用户请用「移动到…」与上下移按钮。
4. TXT 导入只认 `#`、`##` 与「名字：台词」，不推断选项、结局或分支，也不自动创建角色。

## 桌面预览版新增限制

1. 素材文件按内容哈希保存且从不删除；被删除或替换的素材仍留在 `assets/images/`，长篇工程目录会持续增长，首版没有受控回收。
2. 自动保存会重写完整元数据（含全部剧情节点），超长篇工程尚未做压力测试。
3. 导出 HTML 内嵌工程内全部素材（包括当前未被引用的素材），体积随素材数量增长。
4. 原生新建/打开/另存为对话框、未保存关闭的三选一提示，只有逻辑与静态核查，未做人工点击验收。
5. 打包未配置代码签名；Windows 可能提示「未知发布者」。GitHub 下载偶发 502，可设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 重试；重复构建若遇到本机批量删除保护，用 `-c.directories.output=release/<新目录>` 换输出目录。详见 `docs/DESKTOP_PREVIEW.md`。
6. 独立游戏 EXE、多平台、自动更新与发布流程仍属于 M4，未开始。
7. 同一张图既当背景又当角色时，工程里会有两条素材记录（分别带 `bg` / `char`），但磁盘上只有一份图片文件（内容寻址，按哈希去重）。这是有意的：素材的「用途」写在记录上，图片本体不重复存。若以后要按文件统计素材占用，应按 `assets/images/` 的文件数而不是素材记录数。

## 不应误称已完成

- 本地网页可启动、或真实 Electron 隐藏窗口烟测通过，不等于人工可见窗口与交互验收通过。
- JS 单元测试、真实窗口烟测与打包 EXE 自动启动自检通过，不等于人工交互验收、安装向导验收与另一台电脑验收通过。
- 源码导出不包含用户线上浏览器的草稿与上传图片。
- 没有附带开源 AI 模型、外部角色素材或音乐资产。
- 未创建远程仓库、未上传代码、未选择开源许可证、未公开任何素材。
