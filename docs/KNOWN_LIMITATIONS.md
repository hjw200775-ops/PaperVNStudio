# 已知限制与验证边界

## V0.8.2-M3-A 的边界

1. **音画同步测量覆盖「在线音频图 + 渲染层」，不含扬声器/声卡回环**：热态正常 P95=9.1ms（实测），
   但这是「计划时间 vs JS 派发时间」的偏差；AudioContext 排程时间与扬声器实际发声时间仍非同一量（未采集回环）。
2. **掉帧语义已明确**：一次性音频（SFX/Voice）短时掉帧（≤ 500ms）补触发、严重过期（> 500ms）跳过并记录
   `skippedStale`；持久状态命令（BGM/总线/循环/Ducking）永远恢复到当前正确状态。阈值 500ms 是产品定义，非平台测量。
3. **Voice 暂停续播**：`voicePlay(spec.offset)` 用 `HTMLAudioElement.currentTime` 恢复位置，是「元素级」精度
   （约几十毫秒到帧级），不是采样级；与 BGM 的 precise（AudioBufferSourceNode）offset 恢复精度不同。
4. **交叉淡化中途暂停继续**：仍以「目标状态瞬时恢复」，不逐样本还原中间增益（沿用 M2-B 的产品语义，有损上限）。
5. **三份 perfAudioAction 未合并**：正式播放器 / 编辑器试玩 / 时间轴驱动三份音频执行器逐字节等价但独立存在，
   靠一致性契约测试固化，未强行统一（规格明确要求）。
6. **本轮未做**：正式播放器在导出载体（HTML/目录版/EXE）里的逐句演出回归（交 M3B）；跨节点/跨章节时间轴；
   音频裁剪/变速、高级关键帧、视频/Live2D 轨道；1.47 GiB 全链与 900 秒音频浸泡（未改核心音频运行时与资源存储）。

## V0.8.2-M2-B 的边界

1. **暂停继续的 BGM 位置恢复是有损上限**：精确模式（AudioBufferSourceNode）原生支持 offset，
   流式回退用 `currentTime` 恢复；无 offset 时从曲首起播（沿用 V0.8.1 `rebuild` 语义）。
   中途进入「正在淡入/交叉淡化」的 BGM 无法逐样本还原中间增益，定义的产品语义是「以目标状态瞬时恢复」。
2. **一次性音频恢复语义**：暂停即停止正在播的 Voice/SFX；继续从暂停点之后重新触发，
   不续播「已开始未播完」的 Voice 剩余部分（明确产品语义，非无损恢复）。
3. **掉帧跨越事件采用「执行」规则**：视觉时钟掉帧跨越一次性事件时按 `schedule()` 顺序补触发
   （不无声遗漏），极端掉帧下一次性音频会集中触发而非丢弃——这是明确的产品语义。
4. **区间循环与 BGM 素材循环分离**：A 时间轴区间循环（编辑器临时状态）与 B 素材精确音乐循环
   （V0.8.1）各自计数；时间轴回绕时 BGM 按区间起点目标状态重建，不尝试还原「已循环多少圈」的精确相位。
5. **在线音频证据边界**：验收采集的是 AnalyserNode（总线后/master 前）的时域 RMS，证明「有真实输出」，
   不是扬声器/操作系统回环；不把 AudioContext 调度时间等同于实际发声时间；P95 音画偏差量化留待 M3。
6. **本轮未做**：音频裁剪/变速、高级关键帧、视频/Live2D 轨道、跨节点/跨章节时间轴、
   发布运行时一致性改造（M3）；1.47 GiB 全链与 900 秒音频浸泡（未改核心音频运行时与资源存储）。

## V0.8.2-M2-A 的边界

1. **预览是视觉连续预览，不是音视频同步播放**：播放头、舞台演出与波形都真实工作，
   但预览期间**不触发正式音频演出**（`paperPerfAudioDebug().fired = 0`）。界面已明确标注
   「当前为视觉连续预览，完整音频同步将在 M2B 接入」，静音不是故障。BGM 素材自身的精确音乐循环
   （V0.8.1 既有）与「时间轴演出循环预览」是两件不同的事。
2. **波形是只读摘要**：来自真实音频解码的峰值，不实现音频裁剪、变速或破坏性编辑；
   时间轴 1 秒 = 素材 1 秒，BGM 淡入动作只显示素材开头对应秒数，不把整曲压缩进动作时长。
   循环 BGM / 持续 BGM 超出素材时长的部分用斜纹与「持续/循环」标注，不代表已支持音频裁剪。
3. **波形按需生成且受预算约束**：只解码当前节点可见的音频素材，缓存键用素材 SHA-256，
   摘要缓存上限 24 条 / 2 MiB；超 64 MiB 预算的素材拒绝解码，失败时明确标记「波形不可用（按普通片段显示）」，
   不影响工程编辑与播放。同一 `decodeWaveform` 共用 `loadSeq`，因此请求严格串行。
4. **播放区间与循环是编辑器临时预览状态**：不写入工程数据、不混入素材循环配置、不随保存重开保留。
5. **自动跟随有抑制窗口**：用户主动滚动或缩放后 1.2 秒内不自动跟随，避免视图争夺；
   放大到极细粒度时 0.1 秒以下动作仍需手动放大编辑。
6. **本轮未做**：完整实时音频预览、音频事件执行、任意时间恢复持久 BGM、暂停/定位取消旧音频任务、
   AudioParam 调度与避免双 BGM/异步竞态（M2B，见 `docs/V0.8.2_M2B_HANDOFF.md`）；
   音频裁剪/变速、高级关键帧、视频/Live2D、跨节点/跨章节时间轴。
7. **未重复执行**：1.47 GiB 全链与 900 秒音频浸泡 —— 本轮未改核心音频运行时与资源存储。
8. **人工复验待完成**：长时间实际使用体验与第二台机器验收由用户决定；技术验收通过不等于产品体验验收通过。

## V0.8.0 舞台演出的边界

1. **没有多轨时间轴**：并行只能表达「与上一动作同时开始」，不能把某个动作拖到任意时刻，也没有关键帧编辑。动作按列表顺序排布，`↑ / ↓` 改的是「相对上一条」的关系。

3. **没有视频演出、Live2D、骨骼动画、粒子编辑器、AI 生成演出、高级着色器**。角色只有整图位移 / 缩放 / 透明度 / 表情换图 / 上下浮动；表情是「整张立绘换图」，不是局部换脸。
4. **镜头只作用于舞台**：镜头平移与缩放、闪白、渐暗、震动都不影响对话框与 UI。这是刻意的设计，不是遗漏——演出不该干扰阅读。
5. **转场预加载依赖素材已在工程内**：`background.change` 的图必须存在于工程素材（同源 data URI 或受控协议）。未入工程的外部图片不会在切换前被预取。
6. **单节点动作上限 200 条**；时长与延迟各 0–30 秒。超限在保存/校验阶段拒绝，不是运行时静默截断。
7. **演出状态跨句延续，不自动复位**：上一句把镜头推到 110%，下一句仍是 110%，需要显式写一条 `camera.zoom` 回 100%。角色同理——`hide` 之后只有 `show` 能让它重新出现。

9. **跳过动画 = 求终态**：跳过不会播放中间过程，也不会触发依赖「动画完成事件」的音频/回调（本版没有这类回调）。
10. **1 GiB 基准只覆盖打开/播放/切章/跳过/连续播放**：没有覆盖「带演出的大工程导出」（按 V0.7.5 设计，1 GiB 级工程走目录版导出），也没有第二台机器/不同 GPU 的帧率基线。

## 当前已实现

V0.3 网页基线已保留；本分支另外实现了 Windows 桌面预览版：Electron 独立窗口、受控 `paper://` 资源协议、本地工程目录、内容寻址素材、原子保存与备份、旧工程导入、最近工程与启动恢复，并保持离线 HTML 游戏导出。V0.5 新增基础音频（BGM / 音效 / 台词语音）与统一音频运行层。V0.6.1 为导出作品加入标题页、游戏菜单、设置、单槽继续与返回标题，并提供编辑器「完整预览」。V0.6.2 加入标题背景配置与《晚风》内置只读示例（体验 / 复制创作）。逻辑测试、存储测试、导出测试、安全边界测试、真实 Electron 窗口烟测、音频实机验收、播放器实机验收与示例实机验收均已通过。V0.5 人工试听与 V0.6.1 人工验收已由用户确认通过；另一台电脑与安装包仍未验收（见 `docs/ACCEPTANCE.md`）。

## 需要优先处理

1. 网页版仍只在浏览器自动保存一个草稿，切换域名、端口、浏览器或清理站点数据后不会自动迁移；桌面版已改为工程目录 + 自动保存副本 + 备份。网页版迁移仍请下载工程再导入。
2. 运行时模型仍把图片解码为 data URL（内存占用随素材增长）；桌面磁盘格式已改为相对路径 + 内容寻址文件。单图上限 12MiB、工程上限 80MiB 保留。
3. 撤销记录上限 60 步，不跨应用重启；桌面版另有 `backups/` 元数据备份，但不替代版本管理。
4. V0.4.1 已加入角色实体与表情库（每个角色可有多个整图表情变体）；V0.4.2 已加入章节/段落分组与导入预览；V0.5 已加入基础音频，但仍无变量与条件结局系统。表情切换是「整张立绘换图」，不是 Live2D 或分层 PSD 局部换脸。角色与表情已有批量编辑（V0.4.3：勾选多句批量修改说话角色、本句表情与在场角色表情）；音频目前只支持逐句绑定，没有批量音频绑定。
5. 每个节点每个图层每种效果只支持一条起止曲线；不是完整 AE 多关键帧时间轴。持续效果遇到独立场景会重置。
6. 编辑预览按脚本顺序继承，试玩按实际路径；复杂分支的静态预览可能不同，需试玩验证。
7. 读档与后退恢复本句效果终态，不恢复动画中途时间。提前推进时，持续效果按目标值结算。
8. 合成 PNG 只导出原始布局，不包含逐句滤镜和动画。效果随 HTML 游戏导出。
9. 导出播放器包含当前工厂函数，未来模块拆分时要特别验证 HTML 是否仍可独立工作。
10. 当前导出游戏存档键依据工程 ID，重复导出同一工程可共享已有进度；节点被删除后旧存档可能失效。正式版应增加存档版本与迁移策略。
11. 源码较紧凑，可读性有改善空间；不建议同时做大规模整理和文件系统重构。
12. 缺少大规模素材/长篇压力测试、完整跨浏览器矩阵、桌面安全测试、异常断电恢复和 Windows 实机兼容测试。

## V0.5 基础音频的边界

1. 首版切换音乐采用「旧曲淡出 → 新曲淡入」，不做复杂叠轨、交叉淡变或逐轨混音；同一时刻只有一条 BGM 通道。
2. 定点试玩、返回、读档、重开都按目标句状态**从曲首**重建音乐，不追算此前耗时，也不承诺跨会话恢复到音乐的精确秒数。
3. 台词语音每句最多一条、手动导入，不按说话角色自动选音色，不自动等待语音结束推进，不接 TTS / 音色克隆 / 口型同步。语音不阻止玩家继续。
4. 音效每句最多 16 条、同时最多 8 个通道；选项按钮没有专用音频机制（音效绑在选项之后的节点上）。切句会停止上一句未结束的音效并取消延迟任务。
5. 本版可靠支持 16-bit PCM WAV；其他格式只有当前运行环境 `canPlayType` 能接受时才允许导入，不承诺所有浏览器/系统解码相同编码。单文件上限 16 MiB、音频总量上限 96 MiB；时长元数据异步读取，浏览器不给元数据时用 WAV 文件头兜底并明确提示。
6. 分类音量与静音是本机播放偏好（`localStorage`），不随工程走；节点音量属于工程内容。导出的 HTML 带默认偏好，玩家在自己的浏览器里另存一份。
7. 导出 HTML 内嵌全部音频（含当前未被引用的素材），体积随素材增长；导出前会提示增加的体积，超大工程生成可能较慢。
8. 音频素材按内容哈希保存且从不删除；磁盘 `assets/audio/` 会随工程历史增长，首版没有受控回收。
9. 音频路径推导沿用 `entryPlan` 的循环检测与枚举预算。路线太多或存在循环时会停止枚举并提示从更早入口试玩，不会假装路径唯一；同一画面入口前的不同 BGM 不会被 `sceneMode:'own'` 清除。
10. 旧版兼容风险（已在临时副本实测）：V0.4.3 及更早版本能打开含音频工程，但保存时会**静默丢弃 `audioAssets`**，`node.audio` 保留成失效引用（`assets/audio/` 文件仍在磁盘）。请勿用旧版保存含音频工程，并保留备份。后续可考虑 `formatVersion: 2` + `capabilities: ['audio']`，但已发布的旧版不会因为新版加了标识就自动拒绝打开。
11. **未验证项**：人工听审为「待用户试听」（不能声称听感、音色、循环接缝正确）；解锁与音量操作由自动化注入的输入事件完成，不是真人界面操作；第二台电脑与安装包未验证。旧版本已完成的人工/安装包验收未反复重跑。

## V0.6.2 标题背景与内置示例的边界

1. 标题背景只有一个图 + 一个默认样式：没有主题编辑器、标题音乐、标题动画或多套版式；标题与菜单文字始终由程序渲染，SVG 装饰未使用。
2. `titleBackground` 是可选的增量字段，schema 仍为 5。新版能读旧工程，但**旧版本保存会静默丢弃该字段**（标题图丢失，工程仍可打开）；只能靠「不用旧版保存 + 保留备份」防护。
3. 标题背景引用素材 ID：素材被删除后标题页回退默认样式并在检查里报错，不阻断打开与导出。
4. 内置示例是完整副本（45 节点 + 8 张图，约 14MB）；复制后的工程体积与原作相同，升级不会覆盖用户副本，也不会自动同步模板更新。
5. 示例体验窗口使用独立持久分区（`persist:papervn-sample`），存档只在该分区与 `userData` 里；网页版没有体验与复制，只有「下载示例工程」。
6. 复制只接受空目录，不做合并；复制过程中磁盘写入失败的清理路径没有在真实窗口里强制触发（无法安全制造磁盘错误），只做了代码层清理与单元/契约测试。
7. **未验证项**：真人点击与视觉审阅（自动化注入鼠标/键盘事件）、原生目录对话框（验收脚本替换为固定返回值）、第二台电脑与安装包。

## V0.6.1 标题页与菜单的边界

1. 单槽手动存档：没有自动存档、多槽、存档命名、跨设备同步；「继续游戏」只认最近一次手动保存。
2. 菜单打开时只暂停剧情输入，不暂停演出与音频；没有独立的暂停/恢复引擎，也没有快进、文本回顾或自动播放。
3. 标题页没有标题音乐、主题编辑或自定义背景；本轮不制作独立游戏 EXE。
4. 继续 / 读档 / 重新开始按目标句状态从曲首重建 BGM，不保存播放秒数。
5. 「完整预览」与导出使用同一份自包含 HTML，但预览是独立 `BrowserWindow`，不是编辑器舞台内嵌；真人操作未单独验收。
6. **未验证项**：真人点击与人工听审（自动化只注入输入事件）；第二台电脑与安装包；较小窗口只做了按钮不裁切检查，未做多分辨率人工验收。

## V0.4.3 批量的边界

1. 批量只作用于对话/旁白节点；选项与结局节点跳过，不参与批量修改。
2. 场景粘贴是整体替换：不合并两套图层，也不搬运源句的演出；有演出引用冲突时该目标不写入。
3. 演出粘贴只支持「同图层 ID」「唯一角色身份」两种自动匹配，其他情况需要逐个处理（本轮不做映射面板）。
4. 批量修改在场的角色表情时，若该句在分支之后画面不唯一，会跳过而不是按某条路线猜。
5. 多选依赖 `nodes` 播放顺序；未分组句子在树里集中显示，但连选仍按数组顺序。

## V0.4.2 章节的边界

1. 章节/段落只是分组：播放顺序仍由 `nodes` 数组决定，章节顺序与数组顺序保持一致，不支持「章节顺序与播放顺序分离」的排法。
2. 从本句/本段试玩按「最后一个独立场景 → 本句」的实际路径还原；多条路线会合并成同一个状态时不再提示，路线不同时必须由作者选择一条，选中的路线只影响这次试玩。
3. 拖动目前用 HTML5 拖放实现，触屏与手柄不支持；键盘用户请用「移动到…」与上下移按钮。
4. TXT 导入只认 `#`、`##` 与「名字：台词」，不推断选项、结局或分支，也不自动创建角色。

## 桌面预览版新增限制

1. 素材文件按内容哈希保存且从不删除；被删除或替换的素材仍留在 `assets/images/`，长篇工程目录会持续增长，首版没有受控回收。
2. 自动保存会重写完整元数据（含全部剧情节点），超长篇工程尚未做压力测试。
3. 导出 HTML 内嵌工程内全部素材（包括当前未被引用的素材），体积随素材数量增长。
4. 原生新建/打开/另存为对话框、未保存关闭的三选一提示，只有逻辑与静态核查，未做人工点击验收。
5. 打包未配置代码签名；Windows 可能提示「未知发布者」。GitHub 下载偶发 502，可设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 重试；重复构建若遇到本机批量删除保护，用 `-c.directories.output=release/<新目录>` 换输出目录。详见 `docs/DESKTOP_PREVIEW.md`。
6. 独立游戏 EXE、多平台、自动更新与发布流程仍属于 M4，未开始。
7. 同一张图既当背景又当角色时，工程里会有两条素材记录（分别带 `bg` / `char`），但磁盘上只有一份图片文件（内容寻址，按哈希去重）。这是有意的：素材的「用途」写在记录上，图片本体不重复存。若以后要按文件统计素材占用，应按 `assets/images/` 的文件数而不是素材记录数。

## V0.7.5 大型游戏发布的边界

1. **工程格式仍是 data URI 内嵌**：素材总量到约 300 MB 时，`JSON.stringify` 会抛 `Invalid string length`（V8 单字符串上限）；单张图片另有 12 MiB 上限。218 MB 实测可导出，330 MB 在写工程阶段就失败。这不是导出机制的问题——发布产物里的 HTML 只有 162 KB——要支持更大体量必须先拆工程格式（磁盘分离存储 + 按需读取），列在下一轮。
2. 目录版产物没有单文件 SHA-256（`artifact.sha256 = null`、`kind = "directory"`）；需要校验时用 ZIP，或对目录内文件逐个核对。资源文件的哈希在文件名里（内容寻址）。
3. 单文件便携 EXE 仍把整包压进 NSIS 自解压文件，体积与启动时间都不占优势；大工程请用目录版或 ZIP。
4. ~~三个《晚风》Alpha 工程未同步到本机，第一章真实工程验收未完成~~ —— **此条为历史误报**，工程实际在 C: 工作区，V0.7.6-M3 已用隔离副本完成 3/3 验收；见下文「对历史误报的更正」。
5. ~~导出/运行的内存峰值未采样~~ —— V0.7.6-M3 已用 `app.getAppMetrics()` + tasklist 持续采样并产出 `release/memory-profile.json`。
6. 运行时资源协议只放行 `index.html` 与 `assets/` 下的图片/音频扩展名；新增资源类型（如字体、视频）需要同时改协议白名单与 CSP。

## V0.7.6-M3 完成后的边界

M3 已完成「导入即流式落盘 + 内容寻址去重 + 暂存生命周期 + 1 GiB 真实窗口验收 + 内存采样 + Alpha 真实作品验收」，此前记录的 1/2/5 三项缺口已关闭；`tests/audio-store.test.cjs` 的跨表示断言已恢复为 `reused === true`。详见 `docs/V0.7.6_ACCEPTANCE_REPORT.md`。

1. 单文件 HTML 仍保持 **200 MB 上限**，1 GiB 工程按设计走独立游戏目录 / ZIP；不强行支持 1 GiB 单文件 HTML。守卫现在无条件生效（旧代码只在素材是受控 URL 时检查）。
2. 单文件导入上限：图片 64 MiB、音频 16 MiB、音频总量 1.5 GiB；这是安全阈值，不是「无限制」。
3. 主进程只做文件头校验，真实解码由渲染进程的 `<img>` / `Audio` 判定；头部合法但内容损坏的素材会在界面报错，不会被静默写入工程。
4. 内存与性能数据只来自本机单台 Windows 机器（i5-12400F / 32 GiB / Electron 45.3.2），已用 `app.getAppMetrics()` + tasklist 持续采样 212 点覆盖 12 阶段；**未做逐帧 FPS 采样、GPU 显存测量与第二台机器基线**，报告里明确列为未测量，不提供估算值。
5. 运行时素材地址是 `paper://app/asset/…`（不是独立 scheme）：`paperasset://` 在 sandbox 页面里会被拒；未保存的暂存素材用 `paper://app/staging/…`，两者都挂在已验证可用的 `paper` scheme 下。
6. 暂存目录在 `userData` 下，与工程目录分离；只复制 `project.paper.json` 不会带走素材。移动 / 备份工程请用「另存为」或复制整个工程目录。
7. 原生新建/打开/另存为对话框、未保存关闭三选一提示仍未做人工点击验收；目录版导出与预览已用真实窗口自动验收。
8. 独立游戏 EXE 签名、多平台、自动更新与发布流程仍属于后续版本，未开始。
