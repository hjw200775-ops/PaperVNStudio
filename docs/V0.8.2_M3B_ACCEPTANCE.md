## 6. M3B-5 发布载体音画同步（`release/v082m3b-avsync.json`）

复用 M3A 分层口径但明确分离：L1 计划时间（`PF.schedule` 音频槽 start）、
L2 实际派发（`play-requested`）、L3 在线起音（`play-started` / `crossfade` / `precise-crossfade`，
`Date.now` 经 `offset = Date.now() − performance.now()` 对齐到同一单调时钟）、
L4 视觉变化（MutationObserver / `performance.now`）。配对窗口 250ms。

| 载体 | 冷启动 P95 | 热态 P95 | 掉帧 P95 | 最大偏差(热) | 热态样本 | 目标 ≤50ms |
|---|---|---|---|---|---|---|
| A 编辑器时间轴 | 4.0ms | **3.5ms** | 2.3ms | 3.5ms | 5 | PASS |
| C 单文件 HTML | 4.7ms | **1.1ms** | 2.9ms | 1.1ms | 4 | PASS |
| E Windows 独立游戏 | 2.9ms | **2.6ms** | 1.0ms | 2.6ms | 4 | PASS |

- 三载体前台热态音画偏差 P95 均 ≤ 50ms；冷启动与掉帧（注入 350ms 忙循环）**分别报告**，
  不混入热态达标判定。另一次运行中 C 冷态曾出现 168.3ms 尖峰（38 MB HTML 首次解析），
  说明冷态波动大，如实保留，不用冷态数据判定热态达标。
- 计划音频槽 9 个，其中 6 个期望产生起音。实测每轮采到 4–5 个起音事件，
  `unobserved = 1–2`、`duplicateTriggers = 0`、`playbackStats.failed = 0`。
  未观察到的槽主要是 precise/stream 下 BGM 状态命令与 `audioEvents` 12 条滚动窗口
  造成的取证上限，**不能据此判定漏触发**；起播判定以主脚本的 `perfStarts` 证据与
  `playbackStats`（requested/started/completed/failed）为准。
- 每轮热态样本仅 4–5 个，**样本量偏小**，P95 的统计置信度有限，不夸大结论。
- `graph` 均为 `{state:"running", sampleRate:48000, baseLatency:0.01}`，在线音频图确实在运行。
- **不含操作系统扬声器 / 声卡回环输出**；AudioContext 排程时间 ≠ 扬声器发声时间，
  本机没有回环采集条件，不提供估算值。M3A 的 `driver.sync.driftMs` 单独列出，不与音画偏差混算。

## 11. 关键缺陷修复（本轮核心成果）

**`dist/player.js` 把 `!animate||prefersReduced()`（reduced 语义）传给参数名为 `animate`
（「是否按时间轴挂定时器执行一次性音频」）的 `runAudioPerformance`**，造成双向错误：
正常播放时 SFX / Voice / 交叉淡化 / Ducking **完全不触发**，只把终态一次性落地；
读档 / 返回时反而**重放历史一次性音频**。编辑器时间轴预览与编辑器普通试玩走各自驱动，
因此 M3A 的三环境语义一致性测试发现不了，只有真实发布载体才暴露。

- 复现：修复前 `PVN_DEV=1 node scripts/v082m3b-release-verify.cjs` →
  C `run.animate=false`、`playbackStats={requested:0,started:0,...}`（仅标题音乐）；
  E 同样 `requested=0/started=0`。
- 相关代码：`dist/player.js` `runPerformance` → `runAudioPerformance`（约 216 行）。
- 影响范围：单文件 HTML / 目录版 / 独立 EXE 三种发布载体的全部时间轴音频演出；
  读档与返回标题的音效重放。不涉及 `app.js` 编辑器试玩、不涉及 `audio.js` 引擎。
- 已尝试方案：确认为单行参数方向错误，采用最小修复
  `runAudioPerformance(acts,before,after,animate&&!prefersReduced())`；
  `PF.play` 的 `reduced` 语义保持不变。未重构运行时。
- 修复后实机：C/D/E `run.animate=true`；C `requested=4/started=4/completed=3/failed=0`
  且出现 `sfx_chime` 的 `play-started`/`play-completed` 带时间戳事件；E/D 同样有起音证据。
- 防回归：`tests/player-audio-schedule.test.cjs` 固化参数方向、定时器按 `slot.start` 挂载、
  `animate=false` 只落状态、跳过路径取消未执行动作，以及 `app.js` 等价执行器不被误改。
