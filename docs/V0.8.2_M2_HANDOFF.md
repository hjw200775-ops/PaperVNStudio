## 2. 数据模型

唯一事实来源仍是 `node.performance.actions[]`：

```js
{ id, type, target, params, duration, delay, easing, blocking, mode, enabled, start? }
```

- `start` 可选绝对秒（0–86400）；有则 `schedule()` 优先，无则 `after/parallel + delay`。
- `duration` 0–30；`duration = 0` 为零时长瞬时事件（菱形 `◆`，无拉伸手柄）。
- 时间轴**不保存第二份数据**：每次 `render()` 重新 `TL.toTimeline(getActions())`。
- 相对→绝对规则：被操作的动作才写 `start`；未选中的相对动作保持相对，由 `schedule()` 自然跟随。

## 3. 接口定义

`dist/timeline.js`（`const TL = createTimeline(PF)`）：

```js
TL.toTimeline(actions)                    // 物化视图 [{action,id,type,target,start,end,duration,blocking,track,oneShot}]
TL.scrubState(before, actions, t, ctx)    // = PF.stateAt，纯函数
TL.audioSideEffectsAt(actions, t)         // 仅正常播放起点触发（scrub 不调用）
TL.setStart / clearStart / setDuration / setStartAndDuration
TL.totalDuration / blockUntil / trackOf / isOneShotAudio / r3
TL.createDragSession()                    // 单片段移动（M1A）
TL.createResizeSession()                  // 左右边缘拉伸（M1B）
TL.createSnapper()                        // snap / gridForZoom / SNAP_PX=8 / GRID_CHOICES
TL.createSelectionModel()                 // Ctrl/Shift/范围/清空
TL.createBatchDragSession()               // 批量移动，保持间隔、负时间钳制
TL.cloneForClipboard(events, ids)         // 剪贴板快照（含 action 深拷贝与排程时间）
TL.materializePaste(clip, atTime, newId)  // 新 ID + 保留间隔 + 绝对 start
TL.materializeDelete(actions, ids)
TL.groupTracks(events, {showEmpty})       // 固定轨道 + 角色子轨道（显示状态，不写工程）
TL.FIXED_TRACKS
```

`dist/timeline-panel.js`（`createTimelinePanel(opts)`）返回 `{ render, reset, debug, setPlayhead, zoomBy, zoomFit }`。
`opts` 由 `app.js` 的 `initTimelinePanel()` 注入：`getActions / getSelectedId / setSelectedId(id, fromClipDrag) /
commitStart / commitResize / commitBatchMove / paste / deleteIds / restoreRelative / characterName /
scrub / clearScrub / resetScrub / getBaselineDebug / getNodeKey / colorOf / refreshHead / isPlaying / toast / panel / lanes`。

`app.js` 写回操作（每个都只调用一次 `edit()` = 一个撤销步骤）：
`timelineCommitStart / timelineCommitResize / timelineCommitBatchMove / timelinePaste / timelineDelete / timelineRestoreRelative`。
调试钩子：`window.paperTimelineDebug()`、`window.paperTimelineScrubDebug()`、`window.__pvnM3`。

## 4. 组件职责与关键状态流转

```
选中节点 → reset()（清拖动/播放头/选择/基线）→ render()
  → TL.toTimeline() → 轨道/片段/刻度/网格/播放头/吸附线（只读投影）
  → 拖动/拉伸/批量：pointerdown 起会话 → pointermove 只改临时 DOM（不写工程、不建快照）
  → 松手 finish('up') → 一次 opts.commit* → 一次 edit() → render() → schedule() 重算
  → 撤销/重做 → 工程快照恢复 → render() 按动作 ID 恢复选择
```

**坐标系（易错）**：`content` 坐标 `xOf(t)=LABEL_W + t*pps` 用于刻度/网格/播放头/吸附线；
轨道 `body` 已偏移 `LABEL_W`，片段用 `clipX(t)=t*pps`。`LABEL_W=92`，CSS 与 JS 必须同步。

**交互目标保护（M1A 踩过的坑）**：`pointerdown` 时不得重建 lanes，否则浏览器丢失 pointer capture。
`renderPerfUI(skipTimeline)` 就是为此存在；`setSelectedId(id, true)` 必须透传第二个参数。

**验收脚本注意**：合成 `KeyboardEvent` 必须派发到具体元素（如 `#timelinePanel`），
直接 `document.dispatchEvent` 会让 `app.js` 的 `e.target.matches(...)` 抛错（真实按键 target 一定是元素）。
`fs.cpSync` 在本运行环境会被拦截，工程副本用逐文件 `readFileSync/writeFileSync` 复制。
