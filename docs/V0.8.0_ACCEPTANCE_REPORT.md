## 2. 自动化测试（`npm run check`）

24 个测试文件 + 全部源码语法检查（含新增的 `dist/performance.js` 与 4 个新脚本），退出码 0。

其中演出专项 `tests/performance.test.cjs` 的断言全部针对**执行后的状态值**，不是「动作对象存在」：

| 分组 | 断言要点 |
|---|---|
| 数据模型 | 默认值来自类型表；未知类型拒绝 / 剔除；重复 ID 拒绝；时长 0–30、缓动白名单、mode 白名单、参数逐项范围；`NaN` 与字符串数字拒绝；JSON 往返一致；`null` 合法 |
| 调度 | `after` 接在上一个之后、`parallel` 与上一个同时开始、连续并行共享起点、`delay` 叠加、停用动作不进入时间轴、`totalDuration` 取最大值、`blockUntil` 只看阻塞动作 |
| 单动作 | 出现从透明到 1、侧面进入中点位移、终态位移归零；离场终态不可见且透明度归一；移动/缩放/透明度插值；表情解析与失效回退；背景切换；镜头缩放/平移；渐暗；闪白与震动峰值且终态归零 |
| 多角色 | 并行推进互不影响；顺序动作完成后保持终值；无动作图层保持中性 |
| 跳过/重放 | 中途结算 = 播完（深比较）；终态幂等；重放 trail 与逐句播放一致；100 次重复执行后终态不漂移 |
| 分支/重开/换章 | 两条分支结果不同且互不污染；重新开始等于首次进入；换章后新图层从中性开始，不继承旧章节位移与缩放；换句时取消动画后结算 = 整段播完 |
| 语义目标 | `char:<id>` / `bg` / 舞台解析；目标图层被删除不抛错 |
| 预设 | 7 个预设产出的都是合法标准动作，可序列化；没有未知类型 |
| 非法参数 | 越界、类型错误、`NaN` 全部在入口被拒 |

  脚本开始/结束各做一次 SHA-256 指纹（73 个文件），结果 `sourceIntact: true`，原件与原件素材未被修改。
- **三场景 + 一个分支**：清晨的相遇（13 句）· 放学后的走廊（11 句 + 1 个选择）· 夜晚的房间（13 句），

  两者素材与图层几何完全相同，差异只在 `performance`。因为演出与阅读并行，总时长不变（143 s），
  变化的是画面：`before` 全程静止，`after` 有 58 个动作。
- **真实窗口截图**（完整预览窗口，非画布合成）：

## 5. 性能回归（1 GiB 工程）

`npm run perf:bench` → `release/performance-benchmark.json`
工程：1,577,977,792 bytes / 100 张图 / 576 节点 / 12 章（V0.7.6 的 1 GiB 基线）。
素材用**硬链接**挂进 `release/bench-project`，不复制 1.5 GB，也不改原工程。

| 指标 | 实测 | 对照 V0.7.6（`release/memory-profile.json`） |
|---|---|---|
| 打开工程（进程启动 → 运行时指标就绪） | **573 ms** | 1.4 s（含素材导入的完整流程） |
| 播放演出（5 个动作 / 3 句推进） | 528 帧 / 5.31 s，**fps 99.1**，最差帧 59 ms | 新增能力，无基线 |
| 峰值内存（全部 Electron 进程） | **629.4 MB** | 1,118 MB（含 1.5 GB 素材导入，口径不同） |
| 切章（跳到第 12 章并渲染） | 1,216 ms | 新增测量 |
| 跳过演出（连续 5 次点击） | 703 ms | 新增测量 |
| 连续播放 10 句 | 内存 −17.0 MB（654 → 636 MB） | 无单调增长 |
| 强制 GC 后 | 564.6 MB（回落到待机水平） | 无泄漏迹象 |

结论：**没有出现数量级退化**。V0.7.6 的基线峰值包含「导入 1.5 GB 素材」这一最重阶段，
本次基准不导入素材，因此 629 MB 与 1,118 MB 不能直接相减；报告里已标注口径差异
（`verdict.note`），判定只用于发现数量级退化，不用于宣称优化。

## 7. 未完成项与验证边界（如实说明）

1. **多轨时间轴、音频关键帧、视频演出、Live2D、骨骼动画、粒子编辑器、AI 生成演出、高级着色器**
   按任务书要求**未实现**，也没有半成品入口。
2. ~~目录版 / 独立试玩包没有为演出重新打包验证~~ → **已在 M0 补验（见第 4.1 节）**：
   真实编辑器导出目录版 → 启动独立 EXE → 逐句播放演出、分支、存档读档，并做三处终态对照。
   仍未验证的是「1 GiB 级工程带演出的目录版导出」（见第 4 条）。
3. **Windows 可运行版本是免安装目录版**，不是 electron-builder 产出的单文件便携 EXE：
   本机 node 被注入 safe-delete 钩子，electron-builder 解包时 `fs.rm` 被拦成「回收站失败」而中断。
   改用 `scripts/build-win-dir.cjs` 直接组装官方 Electron 运行时，产物同样是双击即用的独立程序，
   并已通过 packaged-smoke 与演出能力检查；**未做代码签名**，首次运行会出现 SmartScreen 提示。
   （导出的**游戏**目录版走的是项目内的 `game-builder` + Electron 运行时复制，不经过 electron-builder，
   因此不受该限制。）
4. **1 GiB 基准没有覆盖「带演出的大工程导出」**：按 V0.7.5 设计，1 GiB 级工程走目录版导出，
   本轮未重新打包该链路；演出动作本身是纯 JSON（58 条约 9 KB），对导出体积无可测量影响。
5. **录屏是 MediaRecorder 直出**，没有 ffmpeg 参与，因此 webm 未写入时长元数据：
   播放器从开头播放正常，部分播放器可能不显示总时长、拖动进度条需要先完整加载。
   验收用途不受影响（`release/probe` 帧抽取已确认画面可解码）。
6. **单机单次实测**：帧率与内存只在当前机器（Windows 10.0.26200 / 集显）采集，没有第二台机器
   与不同 GPU 的基线；没有做长时间（小时级）连续播放的浸泡测试。
7. **人工体验**：本轮未做人工听感 / 手感验收（演出没有音频，视觉验收由截图与录屏承担）。

## 8. 复现步骤

```bash
npm install
npm run check                # 24 个测试文件 + 源码语法检查
npm run perf:window          # 真实窗口演出验收（8 项）→ release/performance-window-smoke.json

npm run wanfeng:v08          # 生成《晚风》三场景样板 + 截图 → release/wanfeng-v08-report.json
npm run wanfeng:record       # 录制试玩视频 → docs/media/v080-wanfeng-play.webm
node scripts/build-win-dir.cjs   # 组装 Windows x64 免安装目录版
node scripts/packaged-smoke.cjs "release/PaperVNStudio-0.8.0-win-x64/PaperVNStudio.exe"
```

`perf:bench` 需要 1 GiB 基线工程：`npm run m3:make-large` 生成后放在 `F:/pvn-1gib-m3`
（或用 `PVN_LARGE=<目录>` 指定）。
