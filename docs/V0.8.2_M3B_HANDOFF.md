## 1. 已冻结的核心模块（M3-B 不要擅改）

| 模块 | 冻结内容 |
|---|---|
| `dist/performance.js` | `schedule` / `stateAt` / `blockUntil` / `commit` / `replay` 核心调度与求值；`start` 字段显式优先、旧工程向后兼容 |
| `dist/player.js` | 正式播放器逐句演出、阻塞结算、读档重放 trail |
| `dist/core.js` | 迁移语义、`checkPerformance`、`bgmAt` / `audioStateAlong` |
| `dist/audio.js` | 核心音频引擎；M3-A 仅加 `voicePlay(spec.offset)` 最小扩展（向后兼容），不改混音/缓存/循环 |
| `dist/timeline-preview-audio.js` | 预览音频驱动（纯逻辑）：事件扫描、Voice 续播、掉帧跳过（STALE_MS=500）、同步采样 |
| V0.7.6 资源存储 | 内容寻址、暂存生命周期、64 MiB 预算 |

## 3. 发布验收需要覆盖的环境（M3-B）

1. **Windows x64 便携版**（`release/PaperVNStudio-0.8.1-win-x64/` 需重建为 0.8.2 版本号）。
2. **目录版游戏**（`release/PaperVNStudio-0.8.0-win-x64/` 对应导出载体）。
3. **单文件 HTML 导出**（自包含，含内嵌音频）。
4. **正式播放器（player.js）** 在上述载体里的逐句推进、阻塞、快进、读档。
5. 第二台机器 / 不同 GPU 的人工验收。

> M3-A 只验证了「编辑器时间轴 + 普通试玩 + 正式播放器的语义一致性」与「编辑器内的音画同步」；
> 正式播放器在导出载体（HTML/目录版/EXE）里的逐句演出回归属于 M3-B。

## 6. 推荐的低成本执行顺序（M3-B）

1. 重建 `release/PaperVNStudio-0.8.2-win-x64/`（便携版），复用 `scripts/v082m2b-ui-verify.cjs` 跑完整 UI 验收。
2. 在便携版上复跑 `scripts/v082m3a-avsync.cjs`（不设 `PVN_DEV`）确认发布载体音画同步一致。
3. 目录版 + 单文件 HTML 导出，跑 `scripts/game-folder-smoke.cjs` / `scripts/game-export-acceptance.cjs`。
4. 正式播放器逐句演出回归（阻塞/快进/读档/BGM 跨句），复用 `scripts/player-acceptance.cjs`。
5. 第二台机器人工验收。

（performance/player/audio 核心）在 M3-B 只做「发布载体回归」，不做功能扩展。
