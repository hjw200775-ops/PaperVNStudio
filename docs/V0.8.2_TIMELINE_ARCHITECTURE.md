# V0.8.2 · 可视化多轨演出时间轴 · 架构说明（M0）

> 基线 `79eb401`（V0.8.1-RC3.1），分支 `feature/v0.8.2-timeline`。
> 本文档是 M0 阶段的架构设计产物，供后续 Hy4 实现正式时间轴界面时直接接手。
> **时间轴不是新的游戏运行时**——它是现有视觉/音频演出数据的统一编辑入口。

---

## 1. M0-1 现状审计结论

仅审计与时间轴直接相关的代码，不重读无关模块。

### 1.1 时间语义：现在是「相对时间」，不是「绝对时间」

`dist/performance.js` 的动作模型（V0.8.0 起）：

```js
// 每个动作：
{ id, type, target, params, duration, delay, easing, blocking, mode, enabled }
//   mode: 'after'（排在上一动作结束之后） | 'parallel'（与上一动作同时开始）
```

`schedule(actions)` 把相对语义换算成绝对时间：

```js
let cursor = 0, lastStart = 0;
for (const a of list) {
  const start = (a.mode === 'parallel' ? lastStart : cursor) + (a.delay || 0);
  const end = start + (a.duration || 0);
  lastStart = start; cursor = Math.max(cursor, end);
}
```

**结论**：当前 `after/parallel` 是「时间轴」的**简写**，`schedule()` 是唯一的时间换算源。
时间轴编辑要做的，就是把「拖动得到的绝对时间」**持久化回动作**，而不是另建一套时间。

### 1.2 求值：`stateAt` 是纯函数，天然支持播放头任意定位

```js
stateAt(before, actions, t, ctx)  // t = 秒；t = Infinity 即终态
```

- 给定 `before` 状态 + 动作表 + 时间 `t`，状态唯一确定。
- **跳过 = t→∞**，因此「跳过」与「正常播完」必然同一终态。
- 这一条对时间轴极其重要：**播放头拖到任意位置 = 用该 `t` 求值**，无需从头重放。

### 1.3 阻塞语义与剧情推进

`blockUntil(actions)` = 最后一个「阻塞」动作的结束时间。播放器据此决定
「点击推进剧情前，是否要先把阻塞演出结算到终态」。时间轴的播放头跨越阻塞点不改变语义，
仍由 `blocking` 字段驱动。

### 1.4 音频副作用：可求值的状态 vs 一次性副作用

| 类别 | 动作 | 进 `stateAt`？ | 拖动播放头时 |
| --- | --- | --- | --- |
| 状态音频 | `audio.bgm.*` / `audio.bus.volume` / `audio.ducking` | ✅ 进 `st.audio` | 可安全求值，不产生播放对象 |
| 一次性音频 | `audio.sfx.*` / `audio.voice.*` | ❌ 无终态 | **不重放**（只在正常播放起点触发） |

这一分离已经存在于 V0.8.1，时间轴直接沿用即可，**不需要改音频引擎**。

### 1.5 数据源、序列化、撤销重做

- 数据源：`node.performance = { version, actions[] }`（schema 6）。
- 序列化：`core.checkPerformance` 只校验不裁剪，动作对象原样写盘；`performance.normalize`
  补齐默认字段。
- 撤销/重做：`app.js` 的 `checkpoint()` 存**整份工程快照**到 `past`/`future`（上限 60 步），
  时间轴编辑只要走 `edit(fn, key)` 就自动获得撤销/重做，**不需要单独实现**。

## 2. M0-2 时间轴数据模型

### 2.1 核心决策：给动作加可选 `start`，`schedule()` 优先读它

**单一数据源 = 动作列表。** 时间轴视图只是动作的「物化投影」，编辑时把时间写回动作的 `start` 字段。

```js
// 动作新增一个可选字段：
start   // 绝对秒（0 ≤ start ≤ 86400）。旧工程没有，时间轴视图才有。
```

`schedule()` 的改动（已完成，向后兼容）：

```js
const explicit = num(a.start) && a.start >= 0;
const start = explicit ? a.start : (a.mode === 'parallel' ? lastStart : cursor) + (a.delay || 0);
```

- **旧工程（无 `start`）**：完全走 `after/parallel` + `delay`，行为与 V0.8.0/0.8.1 逐字节一致，
  无需迁移。
- **时间轴（有 `start`）**：直接按绝对时间排，`after/parallel` 退化为旧版遗留字段（仍保留，
  供动作列表视图回退显示）。

### 2.2 单一数据源映射（唯一事实来源）

```
动作列表 (node.performance.actions)   ←→   schedule() 算出绝对时间   →   时间轴视图渲染片段
       ↑ 单一事实来源                        ↑ 物化视图                     ↑ 只读渲染
       └──────────────── 编辑时写回 action.start ←────────────────────────┘
```

- `toTimeline(actions)` → 事件数组（`{action, start, end, duration, blocking, track, oneShot}`），
  `action` 保留完整引用，**零信息丢失**。
- `setStart(action, t)` → 就地写 `start`（撤销/重做由 `edit()` 的快照机制负责）。

### 2.3 时间轴作用域（推荐 A）

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| **A 单节点局部时间轴** | 每句剧情一个独立时间轴 | ✅ **本轮推荐的最小可用方案** |
| B 跨节点场景时间轴 | 一段场景共享时间轴 | 后续评估，A 已预留扩展点 |
| C 全章节绝对时间轴 | 整章一条固定时长时间轴 | ❌ 不适用（见下） |

**为什么不做 C**：视觉小说是**交互式叙事**，不是固定时长视频。玩家点击、等待、分支、自动播放
都会改变实际剧情时间。把整章强行变成固定长度视频时间轴，会与「点击推进」的交互模型冲突。
A（单节点）天然对齐现有「每句一句演出」的模型，风险最低。

A → B 的扩展路径：时间轴数据本身就是 `{nodeId, actions[]}` 的集合，B 只需把多个节点的
`actions` 合并到一条轨道并共享播放头，无需改数据模型。

### 2.4 轨道划分

`dist/timeline.js` 的 `trackOf(action)` 已实现：

| 轨道 | 动作 |
| --- | --- |
| 剧情/对话 | 由节点本身承载（不在时间轴内） |
| 背景 | `background.change` |
| 角色（按 `char:<id>` 拆子轨道） | `character.*` |
| 镜头 | `camera.move` / `camera.zoom` |
| 特效 | `screen.fade` / `flash` / `shake` |
| BGM | `audio.bgm.*` |
| SFX | `audio.sfx.*` |
| Voice | `audio.voice.*` |
| 混音 | `audio.bus.volume` / `audio.ducking` |

角色按 `char:<id>` 拆子轨道，为未来「多角色子轨道」预留，M1 不强制。

### 2.5 兼容性保证

- V0.8.0/0.8.1 工程无损打开：`start` 字段不存在，`schedule()` 走旧路径。
- 动作顺序、时长、并行关系、阻塞语义**全部保持不变**。
- 旧工程第一次打开时间轴时，`toTimeline()` 物化出绝对时间（只读投影），
  **只有用户拖动时才写 `start`**，不主动改写旧工程。

## 3. M0-3 预览与定位机制

### 3.1 两种模式（严格区分）

| 模式 | 视觉 | 音频 | 实现 |
| --- | --- | --- | --- |
| **拖动定位（scrub）** | 立即 `stateAt(t)` 更新 | 只落状态音频，**不触发** SFX/Voice | `timeline.scrubState()` |
| **正常播放** | rAF 连续更新 | 在正确起点触发一次性音频 | 复用 `PF.play()` + 音频调度 |

### 3.2 已明确的能力

- 从任意时间开始预览：`scrubState(before, actions, t, ctx)` 直接求 `t` 时刻状态。
- 向前/向后拖动：纯函数，无状态累积，回退再前进得到同一结果（已测试覆盖）。
- BGM 位置恢复：状态音频在 `st.audio.bgm` 里是可比较的素材 ID + 音量 + 循环，拖动时用
  `applyAudioState` 落地（同一首不重启）——与现有 V0.8.1 跳过/读档路径完全一致。
- 暂停/继续、调整后重预览、退出释放：沿用现有 `PF.play()` 的 `finish/cancel` 与
  `audio.stopAll/dispose`，不新增机制。

### 3.3 关键不变式（原型已验证）

1. `scrubState` 不产生播放对象、不重放历史一次性音频。
2. 物化 `start` 后的终态与旧 `after/parallel` 终态**逐字段相等**（见 `tests/timeline.test.cjs` §9）。

## 4. M0-4 界面设计（供 Hy4 实现）

沿用现有深色界面风格（`#0f1915` 底 + `#e8f0ea` 字 + `#7ec8a3` 强调），面向**非专业创作者**，
避免专业剪辑软件的复杂度。

├──────────┼────────────────────────────────────────────────┤
│ 背景      │  [背景切换 ▓▓]                                 │
│ 角色·lin  │  [角色出现 ▓▓][移动 ▓▓]                        │
│ 角色·che  │  …                                             │
│ 镜头      │  [镜头缩放 ▓▓]                                 │
│ 特效      │  [渐暗 ▓▓][闪白 ▓]                             │
│ BGM       │  [淡入 ▓▓▓][切换 ▓▓]                           │
│ SFX       │  [♪ 音效 ▓]                                    │
│ Voice     │  [♪ 配音 ▓▓]                                   │
│          ──╂────────────────────────────────────────── 播放头
├──────────┴────────────────────────────────────────────────┤
│  属性面板（选中片段）：类型/目标/时长/缓动/阻塞/参数         │

后续实现（M1 起，非本轮）：添加动作、拖拽改开始时间、拖拽改时长、同轨/跨轨编排、缩放、网格吸附、
多选/复制/删除、撤销重做、基础音频波形、动作列表↔时间轴双向同步。

## 5. M0-5 技术原型（已实现）

- `dist/timeline.js`：`toTimeline / scrubState / audioSideEffectsAt / setStart / clearStart /
  totalDuration / blockUntil / trackOf / isOneShotAudio`。
- `dist/performance.js`：`schedule()` 支持显式 `start`（向后兼容）；`normalize`/`validate` 保留并校验。

  （双击即开，含 5 轨片段、可拖动播放头、状态面板、一次性音频日志）。
- 原型运行截图：`docs/screenshots/v082m0-t0_5.png` / `t2_4.png` / `t4_9.png`。

原型验证了 M0-5 的全部 7 点：动作转时间序列、并行动作排布、`stateAt` 任意时刻状态、
改开始时间更新结果、顺序/并行无损映射、任意时间预览不重放历史音频、旧工程终态一致。
