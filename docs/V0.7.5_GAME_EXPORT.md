# V0.7.5 大型游戏资源分离与独立发布

基线 `823bb30`（V0.7.4）。上一版让**预览**摆脱了 64 MB 的巨型 HTML，但**独立游戏导出**仍然把所有素材 base64 内嵌进 `content/index.html`，`MAX_CONTENT_BYTES = 64 MB` 照旧卡着。本版把同一套资源分离思路搬到发布产物上。

## 一、产物结构

```
<游戏名>-win-x64-独立游戏/           ← 目录版（模式 B）
├── <游戏名>.exe
├── resources/
│   ├── app/                        ← 游戏壳
│   │   ├── main.cjs
│   │   └── content/
│   │       ├── index.html          ← 播放器 + 剧情数据（几百 KB）
│   │       ├── game.json           ← 标题 / 窗口 / releaseId / 格式版本
│   │       └── assets/
│   │           ├── images/<sha256>.<ext>
│   │           └── audio/<sha256>.<ext>
│   ├── app.asar
│   └── …Electron 运行时
└── LICENSE / LICENSES.chromium.html …
```

- 素材**内容寻址**：同一张图/同一首曲只落一份文件，重复引用不会翻倍。
- 原始质量：逐字节复制解码后的原始文件，不转码、不重压缩、不降分辨率。
- 未引用素材不进包：`referencedImageIds()` / `referencedAudioIds()` 先裁剪再落盘（V0.7.4 的分析直接复用）。
- 路径全部相对包内 `content/`，不依赖工程目录、纸间安装目录或开发服务器。

## 二、运行时怎么读

游戏壳（`desktop/game-shell/main.cjs`）的 `papergame://` 协议从「只服务 index.html」扩展为：

| 路径 | 说明 |
| --- | --- |
| `/index.html` | 播放器页面，带 CSP（`img-src 'self' data:`、`media-src 'self' data:`、`connect-src 'none'`） |
| `/assets/…` | 仅图片与音频扩展名白名单，`path.resolve` + 前缀校验，`..` 出不去 `content/` |

安全配置没动：`sandbox`、`contextIsolation`、无 preload / Node，所有 http(s)/ws 请求仍然被拦。资源缺失时返回中文错误（「资源缺失：assets/images/…」）。

## 三、导出方式

| 模式 | 产物 | 说明 |
| --- | --- | --- |
| A · 单文件 HTML | `.html` | 保持原样，素材内嵌、断网可玩；适合小型作品与快速分享 |
| B · 独立游戏目录 | `…-独立游戏/` | 本轮核心；双击 EXE 即可运行，不需要纸间 |
| C · ZIP 发布包 | `…-独立试玩包.zip` | 目录版的压缩；解压即玩，附 SHA-256 与清单 |

单文件便携 EXE（NSIS）保留，但它把整包压进一个自解压文件，体积上不占优势——大工程建议目录版或 ZIP。

`MAX_CONTENT_BYTES` 仍然存在，但现在只约束**播放器页面本身**（几百 KB），素材不再经过这堵墙。

### 小工程（《晚风》示例）

目录版：21 MB 资源，页面 **154 KB**，启动 301 ms，8 图 + 3 曲（素材库 6 曲，排除 3 曲），BGM / 推进 / 返回标题全部正常。

### 1 GB 容量验证：未通过，原因是工程格式而非导出机制

尝试构造 65 张 2048×2048（约 1 GB）的工程时，在**写入工程**这一步就失败了，两个硬限制：

1. **单张图片上限 12 MB**（`project-store.cjs` 的 `MAX_IMAGE_BYTES`），2048×2048 噪声 PNG 约 16.7 MB 直接被拒；
2. **V8 单字符串上限**：工程把素材存成 data URI，`JSON.stringify` 要拼出一个接近 1 GB 的字符串，抛出 `Invalid string length`。

所以当前工程格式的实际上限约在 300 MB 素材量级（218 MB 实测通过、330 MB 已失败）。**导出机制本身不再受 64 MB 约束**，但工程还得先能打开——拆工程格式（磁盘分离存储 + 按需读取）是下一轮的事，本轮按任务要求不重写工程格式。

## 七、已知限制

- **工程格式仍是 data URI 内嵌**：素材超过约 300 MB 时工程本身无法保存/打开（单图 12 MB、JSON 字符串上限）。这是 V0.7.6 的工程格式拆分任务。
- 三个 Alpha 工程仍不在这台机器（`F:`/`Z:` 已搜），《晚风》第一章真实工程验收**未完成**，不以合成工程代替。
- 目录版没有单文件 SHA-256；需要校验时用 ZIP 或目录内逐文件哈希。
- 单文件便携 EXE 仍会把整包压进自解压文件，大工程不推荐。
- 未签名；没有自动更新；只做 Windows x64。
- 未做：多槽存档、剧情变量、UI 设计器、AI / TTS / Live2D。
