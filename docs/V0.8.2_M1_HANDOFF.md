## 2. 数据模型

动作（`node.performance.actions[]` 的元素）：

```js
{
  id, type, target, params,             // 既有
  duration, delay, easing, blocking, mode, enabled,  // 既有
  start                                 // M0 新增：可选绝对秒
}
```

- `mode`：`'after'`（排在上一动作结束之后）| `'parallel'`（与上一动作同时开始）。
- `start`：显式绝对时间，**有则 `schedule()` 优先用它**，无则退回 `after/parallel` + `delay`。
- 单一数据源 = 动作列表。时间轴事件是物化视图，编辑写回 `action.start`。

## 3. 接口定义（`dist/timeline.js` 已实现）

```js
const TL = createTimeline(createPaperPerformance());

TL.toTimeline(actions)            // → [{action, id, type, target, start, end, duration, blocking, track, oneShot}]
TL.scrubState(before, actions, t, ctx)  // → t 时刻舞台状态（复用 stateAt，不触发一次性音频）
TL.audioSideEffectsAt(actions, t)  // → 该时刻应触发的一次性音频（SFX/Voice）
TL.setStart(action, t)            // 写回绝对开始时间（就地改，撤销由 edit() 快照负责）
TL.clearStart(action)             // 删除 start，退回 after/parallel 简写
TL.totalDuration(actions)         // 总时长
TL.blockUntil(actions)            // 最后一个阻塞动作的结束时间
TL.trackOf(action)                // 动作 → 轨道名
```

## 4. 组件职责（M1 建议）

| 组件 | 职责 |
| --- | --- |
| `TimelineView` | 渲染轨道/片段/播放头，处理缩放/滚动 |
| `PlayheadController` | 拖动 → `setT(t)` → `scrubState` + `applyDOM`；播放 → `PF.play` |
| `ClipDrag` | 拖动片段改 `start`/`duration`，写回 `action` |
| `TimelinePanel` | 与动作列表、属性面板双向同步，接入 `edit(fn,key)` |

## 5. 关键状态流转

```
选中节点 → node.performance.actions
  → TL.toTimeline(actions) → 渲染片段（只读投影）
  → 拖动播放头 → TL.scrubState(before, actions, t, ctx) → applyDOM 更新舞台
  → 拖动片段 → TL.setStart(action, t) → edit() 快照 + 重渲染（列表↔时间轴同步）
  → 撤销/重做 → 工程快照恢复（自动，因为 edit() 走 checkpoint）
```
