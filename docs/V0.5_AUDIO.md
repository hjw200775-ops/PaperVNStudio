# V0.5 基础音频 · 开发与验收说明

基线：分支 `v0.4.2-chapters`，上一提交 `f185f16`（V0.4.3 批量编辑）。本版在现有角色、章节、批量编辑、场景解析、`entryPlan`、撤销重做、工程存储与导出架构上增量实现，没有新起一套原型，也没有推送远程或发布版本。

## 一、数据设计（最小增量，不升级 schema 版本号）

`audioAssets` 与 `node.audio` 都是**可选增量字段**，旧工程缺这些字段就等价于「无音频」，画面、剧情、分支、存档行为完全不变。因此保持 `schema: 5`、磁盘 `formatVersion: 1` 不变；`C.migrate()` 只把缺省补齐（`audioAssets:[]`、`audio:null`），不猜测、不生成任何播放任务。

| 位置 | 结构 | 说明 |
| --- | --- | --- |
| `p.audioAssets[]` | `{id,name,categories[],data,mime,ext,bytes,duration,durationNote?}` | `data` 是运行时内嵌 `data:audio/...;base64,...`；`categories` 可含 `bgm/sfx/voice` 多个用途；`id` 只由内容 SHA-256 决定（`au_<hash16>`），重复导入复用同一条 |
| `n.audio` | `null` 或 `{bgm,sfx[],voice}` | `null` / 缺省 = 无指令（BGM 沿用） |
| `n.audio.bgm` | `null` / `{action:'stop',fadeOut}` / `{action:'play',audioId,volume,loop,fadeIn,fadeOut}` | 三态：沿用 / 停止 / 从头播放（同一首也是从头） |
| `n.audio.sfx[]` | `{id,audioId,volume,delay}` | 每次实际进入本句各触发一次；最多 16 条 |
| `n.audio.voice` | `null` / `{audioId,volume}` | 每句最多一条，手动绑定，不按角色名选音色，不接 TTS |
| 播放偏好 | `localStorage['paper-audio-prefs'] = {master,bgm,sfx,voice,muted}` | **不写进工程**；编辑器与导出播放器各自持久化，同一套逻辑 |

磁盘工程（在原有 `project.paper.json` 上新增一个字段）：

```
my-story/
  project.paper.json          audioAssets: [{id,name,categories,mime,ext,duration,file,sha256,bytes}]
  assets/images/<sha256>.png  原有图片
  assets/audio/<sha256>.wav   V0.5：内容寻址音频，永不覆盖、永不删除
  backups/...                 备份恢复时会同时校验图片与音频
```

音频走**独立校验**：`parseAudioDataUrl()`、`AUDIO_FILE_RE`、`AUDIO_CATEGORIES`，图片专用的 `kind` / `data:image` / 宽高解析不会误用于音频。PCM WAV 在落盘时用与导入端共用的 `wavInfo()` 二次校验文件头，损坏文件不会写进工程。

## 二、统一音频运行层（`dist/audio.js`）

`createPaperAudio()` 返回两部分，编辑器与导出 HTML 通过 `toString()` 注入的是**同一个工厂**：

- `pure`：纯计算（`finalVolume`、`normalizeCue`、`wavInfo`、`checkImport`、`readMeta`、`classifyError`），不碰 DOM 与 Audio。
- `runtime`：真正创建播放对象、启动/停止/淡变、管理计时器。

| 规则 | 实现 |
| --- | --- |
| 音量 | `总音量 × 分类音量 × 本次播放音量`，静音直接归零；改音量只改 `volume`，**不重启**声音，淡变中的通道按当前偏好实时重算目标值 |
| 通道 | 单一 BGM 通道、单一语音通道、最多 8 个音效通道（超出停掉最早的） |
| BGM | `沿用` 不动当前播放位置；显式 `play` 从曲首（同一首也一样）；`stop` 淡出后停止；切换采用「旧曲淡出 → 新曲淡入」，首版不做复杂叠轨 |
| 过期任务 | 每次进入句子 `generation++`，淡变回调、兜底计时器、延迟音效任务都校验 generation；快速切句时旧曲立即清理，不会重新响起 |
| 音效 | 每次**实际进入**本句触发一次；编辑、刷新预览、拖时间轴都不触发；切句停止未结束音效并取消未触发的延迟任务 |
| 试听互斥 | 素材试听先停掉游戏音频；进入试玩 / 切句停掉素材试听；「试听本句音频」再次点击停止 |
| 生命周期 | 切句、切工程、退出试玩、关闭播放器都调用 `leave()` / `stopAll()` / `dispose()`，清理播放对象、计时器与淡变任务 |
| 无音频旧工程 | `C.hasAnyAudio(p)` 为假时不创建运行层，也不产生播放任务 |
| 播放失败 | 捕获 `play()` Promise 的拒绝；区分未获播放许可、解码失败、素材缺失，给中文提示与重试指引；失败后状态不显示「正在播放」 |
| 解锁 | 「启用声音」在真实点击里播放一帧静音 WAV 取得浏览器许可；自动化验收用注入的鼠标输入事件，不是真人点击 |

不使用远程音频 URL、在线 CDN 或第三方播放服务。素材全部是内嵌 `data:` 或工程内相对路径。

## 三、路径推导：`entryPlan` 的音频扩展

画面独立（`sceneMode:'own'`）**不等于**音乐独立。原有 `normalizeRoute()` 只保留「最后一个独立画面之后的路径」，会让同一画面入口前不同路线播放过的 BGM 丢失。本版扩展为：

1. 同时计算画面锚点（最后一个 `own`）与音频锚点（最后一条显式 `play`/`stop` 指令，含目标句本身），`trail` 从**更早**的锚点开始，保证 `scene/effects/cast` 与 `audioStateAlong` 都能拿到完整历史。
2. 候选路线的等价键加入「音乐状态」（素材、音量、循环、最后一条指令位置），不同 BGM 的路线不会被合并。
3. 含音频工程即使目标句是 `own` 也不再提前返回空路径；无音频工程保持原来的快速路径，零回归。
4. 只采用「从故事开头可达」的完整路线；若因循环/预算拿不到完整路线，返回「音频历史不完整」并提示从更早的音乐入口试玩或选择路线，不把短路径当成确定状态。
5. 循环检测与 `WALK_MAX_STEPS=4000 / WALK_MAX_ROUTES=24 / WALK_PER_ANCHOR=8` 预算保留；截断时不误报唯一。
6. 路线因画面/表情不唯一但各路线音乐相同时，`audioAgrees:true` 仍把生效音乐显示出来，让作者只选画面路线。

`C.bgmAt(p,nodeId,trail)` 用真实 trail 结算目标句 BGM；返回/读档/重开/定点试玩一律从曲首启动，不追算此前耗时，不承诺跨会话恢复到精确秒数。游戏存档仍只保存 `{id,trail}`，不保存任何运行对象。

## 四、界面

- 左栏新增「音频」标签：导入（选分类）、名称 / 分类 / 时长 / 大小 / 引用数、试听 / 停止、筛选；删除被引用素材时列出每一处引用位置，默认阻止直接删除并引导替换或解除引用。
- 播放偏好区：总 / 音乐 / 音效 / 语音滑块 + 数值 + 静音 + 「启用声音」，状态栏显示当前生效音乐与中文故障信息。
- 右侧「音频」分区：三种音乐模式清楚区分、当前生效音乐或路径不确定提示、音量滑块、循环、淡入淡出（默认收起的高级参数）、多条音效（素材 / 音量 / 延迟）、语音（选择 / 音量 / 试听 / 清除）、「试听本句音频」。
- 导出前弹窗提示音频数量与内嵌后增加的体积。

## 六、素材包与范围

测试素材 `PaperVNStudio-V05-Audio-Test-Kit`：5 个 16-bit PCM WAV，SHA-256 与 `manifest.json` 全部一致。两条英文语音只是功能占位，**没有绑定进正式中文原作**；音乐是功能测试草样，未经人工听审。`manifest.json` 是素材清单，不是工程文件，不能当工程导入。

本版**不做**：TTS、音色克隆、自动配音、口型同步、Live2D、音频剪辑、复杂时间轴、批量音频绑定、变量条件、云服务、独立游戏 EXE。选项按钮没有新增专用音频机制；音效绑定在选项之后的节点上验证。
