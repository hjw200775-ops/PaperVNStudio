# 演出编辑器使用教程（V0.8.0）

面向作者，不涉及代码。读完你会知道：怎么让角色走上来、怎么切背景、怎么推镜头、
怎么让「这一句必须演完」、以及预览与试玩时点击会发生什么。

---

## 1. 演出面板在哪

编辑器右侧「剧情与画面」栏，从上往下会依次看到 **舞台演出**、音频 等面板。
「舞台演出」标题右边的数字是这一句已有的动作数量。

> 演出的作用范围是**当前选中的这一句**。想给别的句子编排，先在左侧剧情列表里点那一句。

面板结构（自上而下）：

1. **7 个预设按钮**（最省事的入口）
2. **动作类型 / 目标** 两个下拉 + **＋ 添加动作**
3. **动作列表**：每条显示「序号 · 类型 · 目标 · 关键参数 · 时长 · 顺序/并行」
   以及 `↑ ↓ 复制 删除` 四个小按钮
4. 点中某条动作后，下方出现**属性区**：参数、时长、延迟、缓动、顺序/并行、阻塞、预览

---

## 2. 七个预设：先用它们把场面搭起来

| 按钮 | 生成的是一串什么动作 |
|---|---|
| 角色淡入登场 | 1 条 `character.show`（淡入，0.8s，阻塞） |
| 角色侧面进入 | `show`（从左侧进入，1.0s，阻塞）+ `bob`（轻微浮动，0.8s，顺序） |
| 角色向前靠近 | 1 条 `character.scale`（140%，1.2s，缓入缓出） |
| 角色退场 | 1 条 `character.hide`（淡出，0.8s） |
| 场景淡入淡出 | `screen.fade` 到黑（0.6s，阻塞）→ `background.change`（直接切换）→ `screen.fade` 回亮（0.6s） |
| 回忆闪白 | `screen.flash` 闪白（0.6s，阻塞）+ `camera.zoom`（108%，1.4s，并行） |
| 轻微屏幕震动 | 1 条 `screen.shake`（强度 1.4，0.6s） |

**预设只是「一次帮你填好几条标准动作」**，生成后就是普通动作，可以随便改参数、调顺序、
删掉其中一条。这不是另一套系统——运行时就只认动作表。

使用前先选好**目标**（角色或背景），否则「角色」类预设会提示先添加立绘。

---

## 3. 手动添加一个动作

以「让林悠从左边走上来」为例：

1. 动作类型选 **角色出现**；
2. 目标选 **林悠**（下拉里列出当前句里带角色的图层）；
3. 点 **＋ 添加动作**；
4. 在动作列表里点这一条，属性区出现；
5. **进入方式** 选 `从左侧进入`；**时长** 填 `1.2`；**缓动** 选 `缓出`；
6. 勾上 **阻塞剧情** —— 这句会让剧情等角色走完再继续。

### 参数按类型自动出现

| 类型 | 你能改的参数 |
|---|---|
| 角色出现 | 进入方式：淡入 / 从左侧进入 / 从右侧进入 / 直接出现 |
| 角色离场 | 离场方式：淡出 / 移出舞台 |
| 角色移动 | X / Y（舞台百分比，0,0 是左上角） |
| 角色缩放 | 缩放 %（10–400） |
| 角色透明度 | 透明度 %（0–100） |
| 切换表情 | 表情（下拉，来自角色设定里的表情表） |
| 轻微跳动 | 幅度 / 次数 |
| 背景切换 | 背景素材 / 转场方式（直接切换、交叉淡化、黑屏过渡、白屏过渡、左滑、右滑） |
| 镜头平移 | X / Y（-50–50） |
| 镜头缩放 | 缩放 %（50–300） |
| 全屏渐暗 | 程度 % / 颜色 |
| 屏幕闪白 | 颜色 |
| 屏幕震动 | 强度（0.5–6） |
| 等待 | 无参数，只靠时长 |

数值超出范围时输入框会拒绝写入（保留上一个合法值），不会把坏数据存进工程。

## 4. 顺序、并行、延迟

- **之后播（顺序）**：接在**上一条动作结束**之后开始；
- **同时播（并行）**：与**上一条动作开始**的同一时刻开始；
- **延迟**：在以上起点上再往后推 N 秒。

所以「两个人一起走上来」的做法是：第一条「角色出现（林悠）」选顺序，第二条「角色出现（林澈）」
选**并行**。再比如「闪白的同时推镜头」：`screen.flash` 顺序 + `camera.zoom` 并行。

调顺序用列表里的 `↑` `↓`。因为关系是「相对上一条」，移动位置会改变语义——
把一条并行动作移到列表第一位，它就变成从 0 秒开始。

---

## 5. 阻塞：什么时候剧情要等

勾了 **阻塞剧情** 的动作，会让「点击 / 空格 / 下一句」在它演完之前**不推进剧情**。

- 大部分「角色登场 / 场景切换」建议勾上，读者才有时间看完；
- 「镜头缓慢推近」「轻微震动」这类氛围动作不要勾——它们应该和台词同时发生；
- 一条演出里有多个阻塞动作时，等的是**最晚结束的那个**。

试玩时如果演出还在播，右下角提示会变成 **「演出中 · 点击可跳过」**。
此时点一下：**动画立即结算到终态**，剧情不动；再点一下才进下一句。
「跳过」得到的画面和「老老实实看完」完全一致——这不是两段代码，是同一个状态求值函数
（`t = ∞` 与 `t = 时长` 在这里是同一件事）。

## 6. 预览：三种方式

| 按钮 | 做什么 |
|---|---|
| **▷ 预览此动作** | 只播选中的这一条，从当前舞台状态起步 |
| **▷ 预览整段** | 按列表顺序播完整段演出 |
| **应用终态** | 不播动画，直接把舞台摆成「演完之后」的样子 |

预览都不写工程、不进撤销栈，纯粹是看效果。想回到布局位置，退出试玩或重新选中节点即可，
也可以点 **应用终态** 之后继续微调。

「**▷ 从头试玩**」则是完整走剧情：演出的阻塞、跳过、跨句延续都会按真实规则生效。
这是验收演出最可靠的方式——预览只验证这一句，试玩验证「三句连起来还对不对」。

## 7. 撤销、重做、保存

演出的所有修改都走编辑器统一的编辑通道，因此：

- `Ctrl+Z` / `Ctrl+Shift+Z` 与其它编辑完全一样（添加、删除、改参数、调顺序都可撤销）；
- 自动保存会把这些动作一起写进工程文件；
- 复制的节点会**断开与原节点的动作 ID**，并同步重映射指向图层的目标，
  两个节点各自独立，不会互相影响。

## 8. 常见问题

**Q：为什么我加了「角色出现」，试玩时角色一开始就是全不透明？**
A：检查这句的动作里是否有第二条会把透明度拉回 100% 的动作（例如并行的「角色透明度 100%」）。
另外「角色出现」永远从透明开始收敛，和图层默认可见无关。

**Q：为什么点了一下就跳过整段？**
A：说明这段演出有阻塞动作，且当时正在播放。第一次点击是「结算动画」，第二次才是「进下一句」。

**Q：切了背景，但导出后背景是空的？**
A：V0.8.0 已经把演出引用的背景素材计入导出引用表；如果仍然空白，检查这条 `background.change`
选中的素材是否在素材库里被删除。

**Q：镜头推近以后，下一句镜头还是推近的？**
A：这是设计如此——演出状态跨句延续。想复位就在下一句加一条 `camera.zoom` 到 100%（或 `camera.move` 回 0,0）。

**Q：角色离场后，下一句又出现了？**
A：只有 `character.show` 会把它重新显示。不写 `show` 的话，离场状态会一直保持。

**Q：为什么对话框没有被「全屏渐暗」盖住？**
A：镜头与覆盖层只作用于舞台，对话框在更上层。这是刻意的：演出不该影响阅读。

## 9. 一条可用的编排习惯

1. 先用**预设**把「人物出场」「场景切换」搭出来；
2. 再补 1～2 条氛围动作（镜头轻推、轻微震动），**不要勾阻塞**；
3. 每句最多 3～5 条动作，超过就该拆句了；
4. 整段编排完，用 **▷ 从头试玩** 连点三遍：一遍正常看完，一遍全程点击跳过，
   一遍中途退出再进入——三次的画面终态应该一模一样。

第 4 条正是 V0.8.0 的验收标准之一：**跳过动画必须得到与正常播放一致的终态**。
